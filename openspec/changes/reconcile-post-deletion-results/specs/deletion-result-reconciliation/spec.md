## ADDED Requirements

### Requirement: 成功删除必须同步当前扫描快照

App 收到 Photos 返回的成功资源 ID 后，MUST 在同一次共享状态更新中从复核箱、当前选择、复核分组和首页任务中移除对应候选，并重新计算剩余候选数量、预计体积和预览缩略图。App MUST 只移除 Photos 确认成功的资源 ID，不得根据请求列表假定全部成功。

#### Scenario: 成功删除后仍有待复核候选

- **WHEN** Photos 确认部分选中资源删除成功，并且当前扫描快照仍有其他可操作候选
- **THEN** 首页任务、候选数量、缩略图和预计体积只包含剩余候选
- **AND** 已成功删除的资源不得再出现在任务复核或复核箱中
- **AND** 首页指标必须标记为“剩余预计可释放空间”

#### Scenario: 成功删除后没有待复核候选

- **WHEN** Photos 确认的成功资源 ID 覆盖当前扫描快照中的全部可操作候选
- **THEN** 首页不得继续展示旧“预计可释放空间”或旧任务卡
- **AND** 首页必须展示“本轮没有待复核项目”空态
- **AND** 首页必须继续提供“重新扫描”入口

#### Scenario: 相似组只剩推荐保留项

- **WHEN** 成功删除后某个复核分组只剩推荐保留项而没有可操作候选
- **THEN** 该分组不得继续生成首页待复核任务
- **AND** 推荐保留项不得因为状态协调被加入删除选择

#### Scenario: 删除成功后不自动重新扫描

- **WHEN** App 已经收到明确的成功资源 ID
- **THEN** App 必须立即协调当前内存扫描快照
- **AND** App 不得自动发起完整照片扫描

### Requirement: 删除成功反馈必须准确描述 Photos 状态

App MUST 在当前扫描周期内保存结构化删除摘要，并在首页和复核箱使用一致的成功数量与预计体积。成功反馈 MUST 明确项目已移至 Photos 的“最近删除”且仍可恢复，不得把候选预计体积表述为已经永久释放的系统空间。

#### Scenario: 第一批项目全部删除成功

- **WHEN** Photos 确认一批项目全部删除成功
- **THEN** 删除摘要必须记录成功项目数量和删除前候选快照对应的预计体积
- **AND** 首页必须展示“已移至‘最近删除’”
- **AND** 首页必须说明项目仍可恢复且空间可能尚未立即释放

#### Scenario: 同一轮扫描分批删除成功

- **WHEN** 用户在同一轮扫描中完成多批成功删除
- **THEN** 删除摘要必须按唯一资源 ID 累计成功数量和预计体积
- **AND** 首页不得只展示最后一批结果

#### Scenario: Limited Photos Access 下删除成功

- **WHEN** 用户处于 Limited Photos Access 且删除至少一项成功
- **THEN** 首页必须同时展示删除成功摘要和“访问范围有限”提醒
- **AND** 成功摘要不得暗示 App 已检查完整照片库

### Requirement: 部分成功和失败必须保留恢复路径

App MUST 分别处理部分成功和全部失败。失败资源 MUST 留在复核箱并保留足够上下文供重试或恢复，成功资源 MUST 从所有当前派生状态中移除。

#### Scenario: 部分项目删除成功

- **WHEN** Photos 返回成功资源 ID 和失败资源 ID
- **THEN** 成功资源必须从复核箱、复核分组和首页任务中移除
- **AND** 失败资源必须留在复核箱并保持选中
- **AND** 复核箱必须展示失败原因和可重试路径
- **AND** 首页成功摘要只能统计成功资源

#### Scenario: 全部项目删除失败

- **WHEN** Photos 没有确认任何请求资源删除成功
- **THEN** 首页扫描任务、候选数量和预计体积不得变化
- **AND** App 不得生成删除成功摘要
- **AND** 全部失败资源必须留在复核箱并展示失败原因

### Requirement: 新扫描必须重置删除后摘要

用户开始新的扫描时，App MUST 清空上一轮删除摘要和旧扫描派生状态，并复用现有扫描进度、取消、中断和完成路径从当前可访问照片库生成新结果。

#### Scenario: 删除成功后重新扫描

- **WHEN** 用户在删除成功后点击“重新扫描”
- **THEN** App 必须立即进入现有扫描进度页
- **AND** 上一轮删除摘要不得继续显示在新扫描结果中
- **AND** 新结果必须基于当前 Photos 权限范围和当前照片库状态生成

### Requirement: 删除结果状态必须可访问

删除成功、部分成功或失败导致界面状态变化时，App MUST 通过明确文本和无障碍语义传达结果，不得只依赖颜色、图标或位置。结果组件 MUST 支持 Dynamic Type，不得遮挡底部“重新扫描”入口或系统 Tab Bar。

#### Scenario: VoiceOver 开启时删除成功

- **WHEN** 删除状态从处理中变为成功且 VoiceOver 已开启
- **THEN** App 必须播报成功项目数量、预计体积、已移至“最近删除”和仍可恢复的信息
- **AND** 用户必须能够继续导航到剩余任务、复核箱或“重新扫描”入口

#### Scenario: 大号 Dynamic Type 显示成功摘要

- **WHEN** 用户使用无障碍字号查看删除成功后的首页
- **THEN** 成功摘要、Limited Access 提醒和空态文案必须完整换行
- **AND** 主要操作的可点击区域不得因文本重排而失效

### Requirement: 删除后回归必须保持默认非破坏性

自动化测试和常规真机 smoke MUST 默认阻止真实 Photos 删除。只有经过确认的破坏性测试计划和显式 opt-in 启动配置 MAY 调用真实删除 API，且禁删配置 MUST 继续优先于破坏性 opt-in。

#### Scenario: 自动化验证成功状态

- **WHEN** UI 或 AppClaw 自动化覆盖删除成功后的首页状态
- **THEN** 测试必须使用确定性的模拟删除结果
- **AND** 测试必须保持真实 Photos 删除禁用

#### Scenario: 执行破坏性真机 smoke

- **WHEN** 已批准的计划使用一张明确可恢复的测试照片验证真实删除
- **THEN** 启动配置必须显式启用破坏性删除且不得包含禁删配置
- **AND** 验证必须确认项目进入 Photos 的“最近删除”并保留恢复路径
- **AND** 测试记录必须说明 iCloud Photos 同步风险
