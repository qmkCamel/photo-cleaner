## Purpose

定义按现有用户任务组织的设置页面、已确认保留的浏览编辑模式，以及首次权限说明和不同原因的空态呈现，帮助用户找到管理入口并理解操作后果，同时保留本地隐私承诺、保护数据和安全删除边界。

## ADDED Requirements

### Requirement: 设置必须以现有管理任务组织

设置标题 MUST 与 Tab 的“设置”一致，按整理管理、帮助与隐私、进阶排列，实际管理入口 MUST 先于详细承诺和模型实验。详细隐私信息 MUST 保持可发现；不得添加无实际能力的开关或修改真实删除授权语义。

#### Scenario: 用户进入设置
- **WHEN** 打开设置 Tab
- **THEN** 首先可以找到已确认保留及数量，之后是如何工作、隐私与帮助，模型实验位于进阶且仍显示真实状态
- **AND** 原有详情与模型路由可用，版本信息不冒充设置项

### Requirement: 保留管理必须区分浏览和批量编辑

保留管理 MUST 默认浏览，图片可只读预览，编辑态提供逐项/全选及“取消所选保留（N）”。空列表 MUST 不展示批量操作；全部取消 MUST 二次确认，取消保护 MUST 明确不会删除照片且可能在后续扫描出现。单次操作 MUST 有结果反馈和撤销，保护与共享状态保持一致。

#### Scenario: 浏览与编辑切换
- **WHEN** 用户进入有保留记录的页面后选择编辑
- **THEN** 浏览时没有每格大取消按钮，编辑时出现选择和批量操作，退出编辑不修改保护记录

#### Scenario: 取消部分保护
- **WHEN** 用户取消所选两项保留
- **THEN** 仅这两项保护被移除，当前共享保护标记同步更新，不触发 Photos 删除
- **AND** 撤销恢复本次移除的保护并移除对应清理选择，不覆盖其他保护决定

#### Scenario: 全部取消及不可访问记录
- **WHEN** 用户选择全部记录执行取消，其中部分资源已不可访问
- **THEN** 确认明确作用于保护记录且不会删除照片，用户取消时所有记录不变；确认后清除对应记录，不把不可访问计为删除成功

### Requirement: 首次说明必须精简但先于系统权限

首次使用 MUST 说明访问用途、本地处理、不上传和不会自动删除，提供一个“开启照片访问”主操作和轻量暂不入口。系统权限请求 MUST 仅在说明之后由明确动作触发。有限权限 MUST 可继续且说明局限，拒绝/受限 MUST 提供适当恢复路径，不循环弹请求。

#### Scenario: 用户暂不授权
- **WHEN** 用户阅读说明后选择暂不
- **THEN** 进入无权限首页，不触发系统权限弹窗，不伪造扫描结果

#### Scenario: 开启访问并得到有限权限
- **WHEN** 用户明确开启访问且系统返回 Limited Access
- **THEN** 可以进入可扫描流程，并明确结果仅基于已授权资源

### Requirement: 空态必须按真实原因提供动作

页面 MUST 区分未授权、未扫描、扫描无候选、本轮处理完和无保留记录，使用对应标题说明及单一主动作，不得以统一成功勾号暗示未执行扫描。权限不足 MUST 不解释为图库没有候选。

#### Scenario: 未扫描和扫描无候选
- **WHEN** 已授权但没有完成过扫描，或已完成且无候选
- **THEN** 前者显示开始整理与扫描相册，后者显示本次范围内暂无候选与重新扫描，不混用完成状态

#### Scenario: 处理完与没有保留记录
- **WHEN** 本轮所有可操作候选处理完，或保留记录为空
- **THEN** 前者显示本轮没有待复核项目与重扫；后者说明可以在照片预览确认保留，隐藏无效编辑/批量操作

### Requirement: 设置和引导必须保留访问性与安全回归证据

关键入口 MUST 支持至少 44×44pt 触控、最大字号及 VoiceOver。回归 MUST 验证跨启动保护与权限状态，显式禁用真实删除并保存语义命名截图；不得把界面重排验收等同于模型质量或真实删除验收。

#### Scenario: 设置与首次使用回归
- **WHEN** 自动化覆盖设置、编辑、全量取消确认、暂不、Limited 和各类空态
- **THEN** 必须断言操作后数据语义，保留成功/取消/恢复和大字号截图，XCUITest 附件使用 keepAlways
