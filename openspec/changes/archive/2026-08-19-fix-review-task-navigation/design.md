## Context

当前真实调用链为 `PhotoScanResultBuilder` 为每个 `CleanupGroup` 生成同 ID 的 `CleanupTask` → `CleanupResultsView` 渲染任务卡 → `AppRootView.onReviewTask` 只传 `task.category` → `CleanupFlowState.selectReviewGroup(for:)` 使用 `firstIndex` 选择该分类的第一个分组。相似识别会产生多个 `.similar` 分组，因此任务 ID 在进入路由前被丢弃，任意相似任务都会打开第一组。

首页任务卡还直接复用 `ThumbnailView`。该组件默认始终渲染选择指示器：未选中时绘制空心圆；但首页缩略图本身不可单独操作，实际点击目标是整张任务卡，因此空心圆没有可执行语义。

本变更只涉及即时本地导航与静态预览，不新增超过 300ms 的用户动作；现有扫描、缩略图加载和删除仍沿用既有交互合同与恢复路径。

## Goals / Non-Goals

**Goals:**

- 同一分类存在多个任务时，点击任一任务都精确打开其对应分组。
- 任务目标失效时安全失败，不把用户带到其他照片，也不改写选择状态。
- 首页预览不展示不可交互的选择控件，详情页继续表达真实选择状态。
- 自动化可以唯一定位任务，并保留关键成功截图。

**Non-Goals:**

- 不合并或重排首页相似任务卡。
- 不修改视觉识别阈值、分组算法或推荐保留排序。
- 不修改复核箱、真实删除开关或二次确认流程。
- 不在本轮重新设计详情页的推荐保留图标。

## Decisions

### 1. 以任务 ID 作为首页到复核页的唯一身份

`CleanupTask.id` 已与来源 `CleanupGroup.id` 对齐，因此状态选择新增按 ID 查找的入口，路由值也携带该 ID。`AppRootView` 在追加导航路径前先确认分组存在；找不到时保持原状态并留在首页。

替代方案是继续传分类并额外传组序号。组序号会在删除协调或任务重建后变化，不能稳定标识同一分组，因此不采用。另一方案是把所有相似分组合并为一张任务卡，属于更大的信息架构变化，不纳入本次 P0 修复。

### 2. 首页显式关闭缩略图选择指示器

`ThumbnailView` 增加默认开启的选择指示器展示参数，复核详情保持现状；首页预览调用显式关闭。这样不复制图片加载、裁切和缓存逻辑，也不会改变详情页已有选择能力。

替代方案是新建首页专用缩略图组件，会重复 PhotoKit 加载和缓存边界，因此不采用。

### 3. 自动化身份使用任务 ID，并提供多相似组确定性场景

任务 accessibility identifier 从分类改为唯一任务 ID。增加一个只用于 UI 测试的双相似组状态，测试点击第二张任务卡后显示第二组标题和候选，并用 `XCTAttachment.keepAlways` 保存首页和详情截图。测试继续传入删除禁用参数。

## Risks / Trade-offs

- [任务 ID 含动态 PhotoKit 分组值，自动化无法预知真实扫描 ID] → 生产身份仍保持唯一；自动化使用确定性测试状态中的稳定 ID。
- [任务在点击前被删除协调重建] → 按 ID 查找失败时不导航且不修改状态，避免落到错误分组。
- [隐藏首页圆框后用户不清楚卡片可点击] → 整卡继续保持 Button、任务标题、数量、标签和无障碍提示，不依赖圆框表达入口。
- [新增 ThumbnailView 参数遗漏调用点] → 默认值保持详情现状，只有首页显式关闭。

## Migration Plan

1. 增加按 ID 选择分组和唯一任务标识测试。
2. 路由切换为任务 ID，并让失效目标安全失败。
3. 首页关闭预览选择指示器，详情保持不变。
4. 运行单元测试、XCUITest、模拟器构建和 OpenSpec 检查，导出并检查命名截图。

回滚时恢复分类路由和首页默认缩略图调用即可；不涉及持久化数据、权限或 Photos 资源迁移。
