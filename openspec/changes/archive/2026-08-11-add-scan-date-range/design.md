## Context

当前调用链为 `CleanupResultsView.onScan` → `AppRootView.startPhotoScan(access:)` → `PhotoLibraryScanning.scan(access:)` → `PHAsset.fetchAssets`。扫描器为照片和视频分别创建相同的 `PHFetchOptions`，但只设置隐藏资源排除和按 `creationDate` 降序，没有日期谓词。因此系统权限决定“App 能看哪些资源”，App 本身无法再限定本次扫描时段。

系统 Photos 权限不支持按时间范围授权。本变更必须把“权限范围”和“扫描范围”作为两个独立概念呈现：权限仍由系统管理，时间选择只影响本次本地 fetch。Limited Photos Access 是有效状态，最终资源集合天然是系统授权集合与日期谓词的交集。

扫描通常超过 300ms，继续遵守现有长耗时动作约束：扫描页提供局部忙碌状态、取消、重试和返回路径。本环境未提供全局 `user-action-contract` skill，因此实现以仓库已有交互为基线，不复制或改写该全局契约。

## Goals / Non-Goals

**Goals:**

- 默认优先整理近期内容，允许用户一键扩大到近三个月或全部可访问资源。
- 让日期边界可测试、可解释，并对照片和视频保持一致。
- 明确当前结果来自哪个范围，避免选择变化与旧结果状态发生语义漂移。
- 保持 Limited Access、本地处理、人工复核、取消/重试和无障碍边界。
- 为新增用户可见状态保留命名自动化截图。

**Non-Goals:**

- 不实现起止日期、自定义天数、按相册、按媒体类型或按修改日期筛选。
- 不持久化用户选择；每次冷启动默认“近一个月”。
- 不改变系统权限申请时机和类型，不尝试按日期申请权限。
- 不改变候选分类、置信度、推荐保留和删除流程。

## Decisions

### 1. 使用离散的 PhotoScanDateRange 值类型

新增 `PhotoScanDateRange` 枚举，固定为 `lastMonth`、`lastThreeMonths` 和 `all`。枚举负责标题、说明、无障碍文案以及基于注入的 `Calendar` 和参考时刻计算起点。

“近一个月”和“近三个月”采用 `Calendar.date(byAdding: .month, value: -1/-3, to:)` 的滚动自然月语义，不按固定 30/90 天折算。例如 8 月 11 日 20:00 的“近一个月”从 7 月 11 日 20:00 开始。日期筛选包含起点和扫描开始时刻，以保证边界稳定。

替代方案是提供自定义日期选择器。该方案会显著增加交互、时区、结束日和结果标识复杂度，超出当前“快速整理近期内容”的需求，因此不采用。

### 2. 在扫描开始时生成不可变 PhotoScanScope

`AppRootView` 保存三个相互区分的状态：用户当前选择、正在执行的扫描范围、最近成功完成结果的范围。用户点击扫描时将当前选择快照传给扫描器和扫描进度页；扫描完成后才更新结果范围。扫描中或结果生成后修改选择，不得追溯改变当前结果标签。

初次授权后自动进入扫描时使用默认“近一个月”。取消后重试继续使用被取消的范围；回到首页后再次点击则使用当前选择。

替代方案是只保存一个绑定值。该方案会让用户在结果页修改选项后，页面无法区分“当前结果范围”和“下次扫描范围”，因此不采用。

### 3. 在 PHFetchOptions 层同时过滤照片和视频

`PhotoLibraryScanning.scan` 接收范围，`SystemPhotoLibraryScanner` 在扫描开始时固定参考时刻，并为照片、视频复用同一范围生成的谓词：有时间范围时使用 `creationDate >= %@ AND creationDate <= %@`；“全部”不设置日期谓词。隐藏资源仍被排除，排序仍按拍摄时间降序。

缺少 `creationDate` 的资源无法证明落在指定时间段内，因此只在“全部”中扫描。这比把未知日期资源悄悄纳入近期范围更可解释、更可复现。

### 4. 范围选择放在首页结果内容中，底部按钮保持固定

首页在照片访问可用于扫描时展示独立范围卡片：未完成扫描时标题为“扫描范围”，已有结果时标题为“下次扫描范围”。首次扫描使用带说明的纵向单选按钮；已有结果且处于普通字号时使用紧凑三选项，避免挤压当前复核任务；无障碍字号自动恢复纵向可换行布局，确保文本与点击区域不被压缩。

已有结果时，页头补充“本次范围：…”；范围卡说明“只影响本地扫描，不改变照片权限”。底部“重新扫描”按钮保持原位置，不因范围卡增高而遮挡 Tab Bar。

### 5. 自动化使用确定性场景并保留截图

XCUITest 从 authorized-home 场景断言默认“近一个月”，切换到“近三个月”并开始扫描，验证扫描页与结果页都显示正确范围。关键结果截图以语义名称附加并设置 `keepAlways`；无障碍字号场景另保留布局截图。

AppClaw 新增独立 P0 Flow，使用稳定的 `truekeep.*` identifier 切换范围并验证结果，不使用坐标或视觉定位。运行报告和逐步截图保留在 `.appclaw/runs/` 作为证据。所有用例继续启用真实删除安全锁。

## Risks / Trade-offs

- [月底日期换算不直观] → 使用 Foundation Calendar 的自然月回退语义，并以边界单元测试锁定行为。
- [扫描跨越当前时刻导致集合变化] → 点击扫描时固定参考时刻，同一轮照片和视频使用完全相同的日期区间。
- [用户修改选择后误读旧结果] → 分离选择范围与完成范围，页头展示当前结果实际范围，卡片明确标为“下次扫描范围”。
- [Limited Access 被误解为完整扫描] → 保留原有有限访问提醒，并明确结果是授权集合与所选范围的交集。
- [无拍摄时间资源丢失] → 近期范围明确排除未知日期，选择“全部”时纳入；在范围说明中保持可解释。
- [范围卡挤压首页] → 使用 ScrollView 内容区和纵向选项，固定底部主操作不变，并运行 Dynamic Type 审计。

## Migration Plan

1. 增加范围模型和日期边界单元测试，再扩展扫描协议与 Photos fetch options。
2. 在 `AppRootView` 接入选择、执行和完成范围状态，保持取消、重试和完成路径。
3. 增加首页范围卡、进度页范围反馈和结果范围标识。
4. 更新 XCUITest、AppClaw 清单与 Flow，保留成功态和无障碍态命名截图。
5. 运行聚焦测试、完整 Xcode 回归、发布预检、OpenSpec 严格校验和 `git diff --check`。

回滚时可恢复原扫描协议并移除范围 UI；由于选择不持久化、扫描结果仍为内存状态，不涉及数据迁移。

## Open Questions

无。第一版固定三个范围，默认近一个月；后续如有明确需求，再单独设计自定义起止日期。
