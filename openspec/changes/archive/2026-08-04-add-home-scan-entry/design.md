# 设计：首页扫描入口与运行周期状态

## Context

Photos 授权状态会跨启动保留，但扫描候选和扫描完成状态只存在于当前运行周期。已授权冷启动因此直接进入首页，却无法从空首页发起扫描。现有 `AppRootView` 已经拥有授权、扫描任务、扫描进度和结果状态；`CleanupResultsView` 是首页结果与空态的实际展示面。

该交互可能超过 300ms，扫描过程继续遵循全局 `user-action-contract`：动作局部状态、非阻塞导航边界、取消与恢复路径由现有扫描进度页承担。

## Goals / Non-Goals

**Goals:**

- 让 Full Access 和 Limited Access 用户始终能从首页开始扫描或重新扫描。
- 准确区分尚未扫描、已扫描无候选和已扫描有任务三种状态。
- 复用现有扫描状态机、取消路径和本地处理安全边界。
- 保持结果列表、Tab Bar、Dynamic Type 和 VoiceOver 可用。

**Non-Goals:**

- 不持久化扫描结果或自动在冷启动后扫描。
- 不修改授权策略、识别算法、默认选择和删除流程。
- 不增加任何破坏性测试路径。

## Decisions

### 1. 由 AppRootView 持有运行周期扫描完成状态

新增 `hasCompletedScan`，与 `cleanupState`、`scanStatus` 和 `scanTask` 位于同一状态所有者。开始新扫描时先重置，只有扫描成功完成后才置为 true。这样不会把“空内存结果”误解释成“已经扫描但没有候选”。

替代方案是把状态放进 `CleanupResultsView`，但子视图无法可靠观察取消、重试和扫描完成事件，会形成第二套状态机，因此不采用。

### 2. 首页只发起动作，扫描仍由现有状态机执行

`CleanupResultsView` 通过 `onScan` 回调请求扫描；`AppRootView` 继续调用既有 `startPhotoScan` 并立即切换到扫描进度页。首页不直接运行扫描，也不复制进度、取消或错误恢复逻辑。

### 3. 根据结果形态放置入口

没有任务时，扫描按钮与空态内容一起滚动；存在复核任务时，重扫按钮通过底部安全区操作区放在 Tab Bar 上方，避免混入任务卡片或遮挡列表内容。

### 4. 使用单一稳定无障碍标识

“扫描相册”和“重新扫描”共享 `truekeep.cleanup.scan`，因为它们是同一个用户意图在不同状态下的文案。UI 测试同时校验 label、可点击性和与 Tab Bar 的几何关系。

## Risks / Trade-offs

- [风险] 运行周期状态不会跨冷启动保留 → 每次冷启动都准确显示“尚未扫描”，符合当前不持久化结果的产品范围。
- [风险] 重扫会清空当前内存候选 → 立即进入现有进度页并保留取消/中断反馈，不在首页静默执行。
- [风险] 底部入口遮挡内容或动态字体 → 使用 `safeAreaInset`，并保留列表底部滚动余量与 UI 几何回归。

## Migration Plan

- 无数据迁移；发布后只影响当前运行周期的首页状态。
- 若需要回滚，可移除 `hasCompletedScan` 和首页 `onScan` 接线，既有授权、扫描与删除状态机不受影响。

## Open Questions

- 无。扫描结果持久化需要独立提案，不在本变更中扩展。
