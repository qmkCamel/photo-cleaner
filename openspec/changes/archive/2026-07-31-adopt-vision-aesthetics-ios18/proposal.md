# 接入 iOS 18 Vision 图片质量评分

## What Changes

将 TrueKeep 最低系统版本提升到 iOS 18，并使用系统内置的 Vision 图片美学评分作为照片总体质量和疑似误拍候选的主要模型信号。保留现有启发式指标作为可解释信号和模型失败兜底，同时使用人脸拍摄质量辅助相似组推荐保留。

## Why

当前相似照片已经使用 Vision feature print，但照片质量、模糊和疑似误拍主要依赖亮度、饱和度、边缘清晰度等手工规则。仓库虽然预留了 Core ML 评分接口，却没有实际模型资产，因此默认路径仍不是模型驱动。

iOS 18 提供 `CalculateImageAestheticsScoresRequest`，可以在设备本地给出综合图片质量分和 utility 标记。将最低版本提升到 iOS 18 后，可以直接采用系统模型，不需要随 App 分发或维护第一方训练模型。

## 范围

- 将 App、单元测试和 UI 测试的最低部署版本提升到 iOS 18。
- 使用 Vision 图片美学评分生成归一化总体质量分。
- 只在美学分极低且图片不是 utility 时，将模型低分作为疑似误拍的保守辅助信号。
- 保留亮度、饱和度和边缘清晰度规则，用于模糊/曝光解释和 Vision 请求失败兜底。
- 使用 Vision 人脸拍摄质量小幅辅助相似照片组的推荐保留排序。
- 保留现有 feature print 相似分组、扫描上限、取消能力、无网络缩略图和复核箱安全流程。
- 更新识别策略、工程说明和聚焦测试。

## 非目标

- 不训练或分发自定义 Core ML 模型。
- 不把 `isUtility` 直接解释为低价值或可删除。
- 不做人物身份、人脸识别、闭眼检测或纪念价值判断。
- 不提高低置信度候选的默认删除选择。
- 不移除启发式失败兜底。
- 不新增云端分析、网络访问或破坏性真机测试。

## 风险

- Vision 美学分是综合黑盒分数，不能单独提供具体清理原因。
- 系统模型分数阈值仍需要真实家庭照片库校准。
- 人脸拍摄质量只适合辅助相似画面比较，不能跨无关人物或场景解释为绝对质量。
- 新增 Vision 请求会增加扫描耗时，必须保留现有视觉分类上限、取消检查和局部扫描状态。
