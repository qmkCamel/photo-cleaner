## Context

当前真实调用链为 `AppRootView.startPhotoScan` 创建并持有 `scanTask` → `SystemPhotoLibraryScanner.scan` 获取照片和视频 → `fetchVisualClassifications` 在视觉分类上限内逐张请求图片 → `PhotoVisualAnalyzer` 一次性生成 pHash、Feature Print、亮度、饱和度、清晰度和质量结果 → `PhotoVisualClassifier` 直接生成最终相似、误拍和模糊分类 → `PhotoScanResultBuilder` 构建复核任务。

`AppRootView` 是用户可见扫描生命周期、扫描范围快照、取消和最终结果发布的所有者；`SystemPhotoLibraryScanner` 是单轮扫描内 PhotoKit 资源、阶段证据与分类过程的所有者。当前扫描器在 `224×224` 目标上使用 `aspectFill`，随后又把 `CGImage` 直接绘制到 `32×32`，因此非方形照片可能先被裁切、再被拉伸。Vision Feature Print 虽配置 `.scaleFit`，但无法恢复此前已经丢失或变形的内容。

当前活跃变更 `fix-local-photo-image-fallback` 已建立 `.fastFormat` 优先、`.highQualityFormat` 本地回退的请求顺序。本变更保留该顺序和 `isNetworkAccessAllowed = false` 边界，并在粗筛和复核尺寸上复用它。

扫描和候选复核均属于超过 300ms 的用户动作，通用交互继续引用全局 `user-action-contract`；本设计只记录 TrueKeep 的阶段名称、状态所有权、取消边界和本地照片安全差异，不复制通用契约。

## Goals / Non-Goals

**Goals:**

- 保证横图、竖图和全景图在视觉分析前保留完整构图、正确方向和宽高比。
- 以 `224px` 粗筛控制全量成本，只对有理由复核的候选读取约 `512px` 本地图片。
- 使用复核证据重新判断相似关系、模糊风险、人脸质量和推荐保留，允许移除错误候选或拆分粗筛组。
- 用底层本地资源摘要确认字节级精确重复，避免缩略图碰撞造成误报。
- 在资源缺失、取消和低电量状态下保持有界、本地、可恢复和保守默认值。
- 为算法结果、性能边界和用户可见阶段提供可重复测试与命名截图。

**Non-Goals:**

- 不对视觉分类上限内的全部照片执行 `512px` 或原始资源读取。
- 不引入 MobileCLIP、FastViT、MobileNet 或其他新模型资产。
- 不把重新编码但画面相同的文件称为字节级精确重复；它们仍可保留在视觉相似复核组。
- 不修改扫描日期范围、Photos 权限说明、任务信息架构、复核箱和删除确认流程。
- 不为识别下载 iCloud 资源，不进行真实照片删除自动化。

## Decisions

### 1. 分离粗筛证据、复核证据和最终分类

扫描器内部引入三个不可变阶段值：`PhotoCoarseEvidence`、`PhotoRefinedEvidence` 和 `PhotoFinalClassification`。粗筛完成后先生成复核资产 ID 集合；所有复核完成或降级处理结束后，才一次性构建最终分类和 `CleanupFlowState`。用户界面不得看到会在复核过程中不断变动的临时分组，避免任务 ID、推荐保留项和路由目标抖动。

替代方案是在每张 `512px` 图片返回后直接修改现有 `PhotoVisualClassification`。该方案会让分组在扫描过程中重排，取消时还可能发布半成品结果，因此不采用。

### 2. 第一阶段保留 `224px` 上限，但全链路保持宽高比

粗筛请求继续使用 `224×224` 目标框，content mode 改为 `.aspectFit`，并继续执行快速本地请求优先、高质量本地请求回退。方向必须在生成视觉证据前规范化。

`PhotoVisualAnalyzer` 不再把内容直接拉伸到固定正方形。分析栅格器按原图比例缩放并记录有效内容区域；亮度、饱和度和清晰度只统计有效内容，填充区不得进入指标。pHash 回退实现必须保留完整构图，并把宽高比纳入可比较性约束；不同宽高比的照片不得仅因填充或压缩产生相似命中。Feature Print 继续使用 `.scaleFit`。

替代方案是只改 PhotoKit 的 content mode。它能够避免第一次裁切，但不能修复后续 `32×32` 拉伸，因此不采用。另一方案是继续中心裁切以简化 hash，会丢失主体和边缘内容，也不采用。

### 3. 第二阶段只复核粗筛候选，并覆盖相似组全部成员

复核集合包含：

- 每个粗筛相似组的全部成员，包括暂定推荐保留项；
- 达到粗筛疑似模糊或疑似误拍门槛的单张照片；
- 与上述门槛接近、由策略明确纳入的边界候选。

每个复核资产请求约 `512×512` 的 `.aspectFit` 本地图片，重新生成清晰度、Vision 图片质量、可用的人脸拍摄质量和 Feature Print。最终分类器只在原粗筛候选子图内重新比较：可以保留、拆分或移除粗筛相似关系，并基于复核后的总体质量为主、人脸质量为辅重新选择推荐保留项。最终稳定分组 ID 从复核后的成员 ID 集合生成。

只复核暂定推荐项无法与组内其他成员公平比较，因此不采用。全量 `512px` 能简化流程但会让数百张照片承担不必要的解码和 Vision 成本，也不采用。

### 4. 粗筛和复核使用分阶段、可标定的质量策略

现有清晰度阈值与 `32×32` 拉伸采样绑定，不能直接用于新的宽高比栅格或 `512px` 复核。实现必须将粗筛阈值、复核阈值和最终风险合并策略集中到 `PhotoVisualAnalysisPolicy`，避免散落魔法数字。

聚焦测试使用方向、宽高比、模糊程度和曝光可控的 fixture 锁定单调性；真实模拟器照片集记录粗筛候选数、复核候选数、拆组数、最终候选数和扫描耗时。没有标注数据前，不用主观的“准确率提升”代替证据。

替代方案是沿用现有阈值再根据肉眼结果微调。该方案无法区分算法变化与样本偶然性，因此不采用。

### 5. 字节级精确重复使用本地底层资源摘要

精确重复确认只在粗筛/复核已经高度相似的组内执行，不遍历整个相册。`PhotoDuplicateVerifier` 使用 `PHAssetResource.assetResources(for:)` 选择可比较的主资源，并通过 `PHAssetResourceManager.requestData` 流式输入 CryptoKit SHA-256；请求选项始终关闭网络访问，数据不落盘、不上传。

普通静态照片只有可比较主图片资源摘要一致时才标记为字节级精确重复。Live Photo 必须同时确认主图片和配对视频资源；任一必要资源缺失、类型不一致或本地不可用时，不得标记为精确重复。编辑版本、重新编码文件或仅像素相近但字节不同的照片继续作为视觉相似候选，不冒充字节级重复。

替代方案是用 `224px`/`512px` pHash 或 Feature Print 直接确认精确重复，存在缩放、编码和碰撞误报，不采用。全量读取原始资源成本过高，也不采用。

### 6. 本地资源缺失按阶段保守降级

- 粗筛图片在快速和高质量本地路径都不可用：跳过该照片的视觉识别，继续其他资源。
- 粗筛成功但 `512px` 复核不可用：可以保留粗筛复核候选，但标记为未完成复核/低置信度，默认不得选中删除，也不得标记为精确重复。
- 原始资源摘要不可用：只取消精确重复确认，不抹除已有视觉相似结果。
- 任一阶段均不得把 `isNetworkAccessAllowed` 打开，不因单张失败终止整轮扫描。

这种降级比“复核失败就彻底丢弃候选”更符合信任优先原则：用户仍可看到可能值得检查的项目，同时系统不会把缺失证据解释为更高置信度。

### 7. 扫描状态由扫描器报告真实阶段，AppRootView 决定是否发布

`PhotoLibraryScanning` 增加可发送的进度更新通道，报告 `.coarseAnalysis(completed:total:)`、`.candidateRefinement(completed:total:)` 和 `.finalizing`。`AppRootView` 继续持有 `scanTask`、`activeScanID` 和最终 `CleanupFlowState`，只接受当前 scan ID 的更新；`ScanProgressView` 显示当前阶段、局部计数和真实状态，不再用固定百分比暗示全局精度。

扫描任务状态必须独立于当前展示页面。用户从扫描进度页返回首页或切换到不依赖扫描结果的 Tab 时，本轮扫描继续运行；首页以动作局部状态提供“正在快速分析/正在复核候选”入口，用户可以重新打开进度页并取消。依赖最终结果的任务卡在扫描完成前保持未发布，避免旧结果和新一轮半成品混用。

取消检查位于每张粗筛、每张复核和每次资源摘要请求之间；可取消的 PhotoKit 资源请求需要保存 request ID 并在任务取消时撤销。取消后丢弃本轮瞬时证据，不发布部分结果，保留同一扫描范围的重新扫描入口。页面继续说明未删除、移动或上传照片。

### 8. 控制内存和并发，不长期缓存高清候选

粗筛与复核按小批量、有限并发处理；`512px` 解码缓冲、Vision 结果和资源摘要上下文在单项或小批完成后释放。可以用 `PHCachingImageManager` 预热当前复核小批次，但缓存参数必须与实际请求一致，并在阶段结束或取消时停止缓存。原始资源摘要严格串行或使用极小并发，避免同时读取多个大文件。

## Risks / Trade-offs

- [候选较多时扫描时间增长] → 只复核粗筛候选，沿用视觉分类上限和低电量上限，展示真实阶段并记录扫描耗时。
- [新栅格改变历史 pHash 和清晰度分布] → 分阶段阈值、可控 fixture、旧新指标对照和真实相册 shadow 记录共同标定。
- [复核后分组被拆分导致任务标识变化] → 只从最终成员生成稳定 ID，最终分类完成前不发布任务。
- [部分候选本地 512 资源不可用] → 降为未复核、低置信度且默认不选中，继续扫描其他资源。
- [原始资源很大或 Photos 分块回调频繁] → 流式摘要、有限并发、及时取消，不把完整资源聚合进内存。
- [Live Photo 只比较静态帧造成误报] → 精确重复必须同时确认图片和配对视频；证据不完整时保持视觉相似。
- [字节不同但画面完全相同无法进入精确重复] → 明确产品语义：字节级重复与视觉相似分开，宁可保守不升级。
- [阶段状态和离页继续扫描增加协议与 UI 复杂度] → 生命周期仍由 `AppRootView` 单点持有，扫描器只发送不可变进度事件和最终结果，首页只展示同一 active scan ID 的动作局部状态。

## Migration Plan

1. 先引入分析策略、宽高比栅格和阶段证据模型，用单元测试锁定现有本地回退与安全边界。
2. 接入 `224px` 粗筛和 `512px` 候选复核，在测试数据上标定分阶段阈值并记录旧新结果差异。
3. 增加候选内原始资源摘要确认和 Live Photo 保守规则。
4. 扩展扫描进度协议和 UI，补齐取消、重试、VoiceOver 与 Dynamic Type 验证。
5. 在关闭真实删除的模拟器/真机 smoke 中验证真实 Photos 资产，保留 AppClaw 报告和命名截图后再考虑发布。

回滚时通过扫描策略关闭候选复核和精确重复确认，保留已修正的 `224px aspectFit` 与本地回退；本变更不持久化摘要或迁移用户数据，因此无需数据回滚。

## Open Questions

无。首版固定使用 `224px` 粗筛、约 `512px` 候选复核；字节级精确重复采用本地底层资源 SHA-256，重新编码副本仍按视觉相似处理。
