## Context

当前复核调用链为首页任务按唯一分组 ID 进入 `ReviewGroupView`，用户逐张选择后只能加入复核箱，再由 `ReviewBinView` 展示 `DeleteConfirmationSheet` 并调用 `PhotoLibraryDeleting`。`CleanupFlowState` 是首页任务、复核分组、当前选择、复核箱和结构化删除摘要的共享状态所有者；远端最新实现已经通过 `reconcileDeletedAssets` 按 Photos 实际成功 ID 重建这些派生状态。

直接删除属于可能超过 300ms 的破坏性用户动作，继续引用全局 `user-action-contract`。本设计只说明 TrueKeep 的二次确认、状态对账、当前页面完成态和测试禁删差异，不复制通用交互规则。

## Goals / Non-Goals

**Goals:**

- 允许用户对复核组中已经明确选中的候选直接发起删除，不强制先进入复核箱。
- 保留应用内二次确认、Photos 系统删除语义、iCloud Photos 风险和“最近删除”恢复说明。
- 删除期间提供动作局部 loading、防重复提交和失败恢复，结果返回前不提前移除候选。
- 复用共享删除结果对账逻辑，立即同步复核组、复核箱、首页任务、预览、预计体积和结构化删除摘要。
- 当前组全部处理后继续展示稳定完成态，返回首页时显示已经同步的结果。

**Non-Goals:**

- 不自动删除扫描候选，不提高视觉候选置信度，也不改变推荐保留和默认选择规则。
- 不取消复核箱，不绕过应用内二次确认或 Photos 系统确认。
- 不增加跨启动删除历史、网络请求、第三方依赖或“最近删除”管理能力。
- 自动化和常规 smoke 不执行真实 Photos 删除。

## Decisions

### 1. 直接删除与加入复核箱保持同层级

复核页把“加入复核箱”和“直接删除”放在同一主操作区域。两者只读取当前分组中明确选中且非推荐保留的资源 ID；无选择时同时禁用。无障碍字号下改为纵向全宽排列，常规字号优先横向排列并允许在空间不足时回退到纵向。

替代方案是把直接删除放进更多菜单。该方案降低可发现性，也无法体现它与加入复核箱是两条平行路径，因此不采用。

### 2. 复用同一删除确认组件和删除服务

`DeleteConfirmationSheet` 从复核箱私有组件提升为模块内共享组件。复核页在确认后调用同一个 `PhotoLibraryDeleting`，确认按钮展示局部进度，执行期间确认和取消不可重复触发，结果返回前保留当前候选数据。

直接调用 Photos API 或建立第二套确认文案会让风险提示和安全策略漂移，因此不采用。

### 3. 直接删除复用共享结果对账

`CleanupFlowState.applyDirectDeletionResult` 只负责直接删除入口特有的错误文案，然后调用既有 `reconcileDeletedAssets`。对账始终以 Photos 返回的成功资源 ID 为准，从复核箱、选择、复核分组和首页任务移除成功项，并累计结构化删除摘要。部分失败时失败候选仍在原分组中并保持选中；全部失败时共享状态不变。

替代方案是在 `ReviewGroupView` 中直接修改数组。该方案会绕过首页任务重建和删除摘要，导致多个入口行为不一致，因此不采用。

### 4. 页面使用本地完成快照承接被移除的当前组

共享对账会删除已经没有可操作候选的分组。若直接删除清空当前组，`ReviewGroupView` 在应用共享状态前生成删除后的本地完成快照，用于继续展示“删除已完成”、零剩余候选和禁用操作；首页共享状态仍立即移除对应任务。用户返回首页后页面销毁，不把完成快照写回业务状态。

自动切回首页会让成功反馈过于突然，保留空分组到共享状态又会产生不可达的幽灵分组，因此采用页面本地快照。

### 5. 自动化使用双重禁删保护

UI 测试始终携带 `-TrueKeepDisablePhotoDeletion`。成功路径只在 DEBUG 构建下通过 `-TrueKeepUITestSuccessfulPhotoDeletion` 返回确定性成功结果；失败路径验证安全锁原样保留候选与选择。禁删配置继续优先，测试不得调用真实 Photos 删除。

## Risks / Trade-offs

- [远端状态重构导致重复对账] -> 直接删除只调用共享 `reconcileDeletedAssets`，不维护第二套任务同步算法。
- [当前组被移除后页面索引越界] -> 在共享状态变更前生成本地完成快照，完成态不再读取已删除分组。
- [大号字体挤压两个主操作] -> 无障碍字号使用纵向全宽布局，并运行系统无障碍审计。
- [重复点击产生多个 Photos 请求] -> 使用页面局部 `isDeleting`、禁用确认和取消，并在服务调用前拦截重复提交。
- [测试误删真实照片] -> 默认禁删参数与 DEBUG 模拟结果并用，保留失败安全锁回归。

## Migration Plan

1. 增加直接删除选择、确认和局部 loading，并复用现有删除组件与服务。
2. 把直接删除结果接入共享对账模型，补齐成功、部分成功、失败和同分类多任务测试。
3. 运行完整 Xcode 回归、无障碍审计和非破坏性模拟器 E2E，保留必要截图。

回滚时移除复核页直接删除入口、入口特有错误态和 DEBUG 成功模拟参数；复核箱删除与远端已有的共享结果对账保持不变。

## Open Questions

无。首版保留复核箱作为可选缓冲区，直接删除只服务于用户已经在当前分组确认清楚的候选。
