## Context

扫描器在本地视觉分类阶段计算组内质量排序，并把结果写入 `PhotoVisualClassification.recommendedKeep`，随后 `PhotoScanResultBuilder` 映射为 `CleanupCandidate.recommendedKeep`。当前任务构建、预计空间、批量选择、复核页布局、徽标、文案和 VoiceOver 都直接读取该布尔值，因此只隐藏徽标会留下大量不可见的推荐行为。

`CleanupCandidate.confirmedKeep` 是用户明确决定的持久化保护状态，必须与算法推荐继续分离。关闭推荐不能削弱确认保留、复核箱、直接删除和二次确认。此次没有新增长耗时动作，不改变现有扫描与删除的 `user-action-contract` 行为。

## Goals / Non-Goals

**Goals:**

- 通过一个产品级开关同时关闭推荐的展示、文案、选择过滤、预计空间影响和无障碍语义。
- 保留底层质量比较和数据字段，未来重新评估推荐方案时可以低成本恢复或替换。
- 推荐关闭时让相似组默认零选择，避免用隐藏排名替用户决定哪张应保留。
- 保持用户确认保留为硬保护状态，并保证全部删除入口继续遵守二次确认与测试禁删策略。

**Non-Goals:**

- 不移除 Vision Feature Print、美学质量、人脸拍摄质量或内部排序测试。
- 不新增用户可见设置项，也不允许 Release 通过远端配置临时打开推荐。
- 不改变相似分组阈值、任务路由、确认保留存储或 Photos 删除服务。

## Decisions

### 1. 使用单一静态产品开关和“有效推荐”语义

在共享模型层增加默认值为 `false` 的 `TrueKeepFeatureFlags.recommendedKeepEnabled`，并由候选暴露只读的有效推荐语义。任务、选择和界面只能读取有效推荐，不直接读取原始算法标记。这样底层仍可记录和测试排序结果，但产品层不会部分泄漏推荐行为。

替代方案是删除所有推荐计算和字段。该方案会扩大扫描器改动和回归范围，也不利于后续使用真实样本重新评估，因此不采用。仅在 `ReviewGroupView` 隐藏徽标会让批量选择、预计空间和首页文案继续依赖推荐，同样不采用。

### 2. 推荐关闭时相似组默认零选择

真实扫描构建和确定性样例都把相似组初始选择设为空；分组导航重新进入相似组时也重复应用该规则。用户逐张选择后，复核箱和直接删除读取真实选择。批量操作是明确用户动作，选择当前组全部未确认保留候选；再次点击清空当前组。

替代方案是继续默认选择内部排名之外的照片。该方案仍然依赖当前被判定质量不足的推荐器，只是把依赖隐藏起来，因此不采用。把所有相似照片默认选中会提高误删风险，也不采用。

### 3. 任务与复核文案使用中性表达

相似任务使用“请逐张确认”等中性文案；精确重复只陈述本地确认内容一致，不再声称 App 推荐一张。复核组解释只说明照片相似或内容一致，并要求用户自行确认。推荐专属三列大图、书签徽标和 VoiceOver 前缀全部由有效推荐开关控制。

### 4. 用户确认保留优先级不变

`confirmedKeep` 继续从逐张选择、批量选择、预计空间和复核箱中排除。即使同一候选保留了原始算法推荐标记，推荐开关关闭时也只展示“已确认保留”这一用户决定。

### 5. 规格归档按依赖顺序协调

`add-direct-review-deletion`、`add-confirmed-keeps`、`refine-photo-analysis-pipeline` 和 `reconcile-post-deletion-results` 中包含推荐相关历史增量。归档时先合入这些基础变更，再归档本变更；如果顺序无法保证，必须先把旧增量协调为推荐关闭后的最终 Requirement，避免旧规格覆盖本变更。

## Risks / Trade-offs

- [内部仍计算排序，存在未来调用方直接读取原始标记的风险] → 全仓搜索原始 `recommendedKeep` 的产品层读取，只允许扫描内部与测试保留；用单元测试覆盖有效推荐屏蔽。
- [相似组默认零选择增加操作次数] → 保留逐张点击和批量选择；以降低不可信推荐造成误删的风险为优先。
- [批量选择可能选中整组相似照片] → 批量操作必须由用户明确触发，确认保留项始终排除，删除仍需应用内二次确认和 Photos 系统确认。
- [历史截图和文档继续展示推荐] → 更新当前流程与识别策略文档，并保留新的关闭态 E2E 截图；历史归档证据不回写。

## Migration Plan

1. 先添加关闭态测试，确认旧实现会暴露推荐或预选相似照片。
2. 加入产品开关和有效推荐语义，协调状态、扫描结果、样例与界面。
3. 运行禁用真实 Photos 删除的 UI E2E，保留推荐关闭和手动选择截图。
4. 完成完整 Xcode 回归、OpenSpec 严格校验和差异检查后发布。

回滚时只把产品级开关恢复为启用，并恢复对应当前流程文案和关闭态测试；底层排序实现无需迁移数据。
