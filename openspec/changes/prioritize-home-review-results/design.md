# 第二轮设计

## Context

当前 CleanupResultsView 在任务前放扫描技术报告和下次范围；扫描各阶段已有进度来源和可恢复会话。以 [总方案](../../../docs/13-interaction-redesign-plan.md) 重排信息，复用现有任务唯一 ID 和共享扫描所有者。

## Goals / Non-Goals

目标：结果优先、范围归属清晰、扫描不抢占导航。非目标：改变范围日期算法、识别/缓存/覆盖逻辑、新增后台扫描调度或网络资源下载。

## Decisions

### 首页和扫描设置

有任务时不新增“开始清理”大按钮，直接让任务卡承载进入复核。重新扫描在导航工具栏以可读文字展示，不藏在省略号里；技术详情用次级“扫描详情”入口。有限访问和不可读取提醒仍在任务前，以短摘要加详情展开，不以“100% 完整”误导。

未扫描时一个“扫描相册”主按钮；已扫无候选/处理完时一个“重新扫描”主按钮。点击打开范围 sheet（三个选项、说明、开始/取消）。本地 draftScope 只属于表单；默认近一个月，后续取最近提交范围。取消即丢弃草稿；确认才更新偏好、锁定范围快照、发起扫描并进入进度。

扫描报告增加可选完成时间，成功提交时记录并显示。已有未记录时间的会话不补造时间，也不把恢复记录的时刻冒充扫描时间；不提升会话版本或增加迁移分支。

### 扫描状态所有权

沿用现有共享扫描任务、取消令牌和会话状态。视图状态只含路由/表单草稿；不能让多个 Tab 的 onAppear 各自启动扫描。运行中隐藏/禁用新扫描入口，点击状态条只重新进入现有进度页。

保留 committedSession（旧结果、复核决定、删除摘要）直到新扫描成功；pendingRun 只暴露阶段、范围、局限和进度，不作为可操作的半成品任务。提交时读取最新保留记录、成功删除 ID、权限状态，防止扫描期间的决定被旧快照覆盖。失败/取消丢弃 pendingRun；重试沿用该轮范围但重新取开始时刻。

### 进度和完成路由

一个固定位置进度区，阶段未知总量时不显示虚假百分比；有阶段计数则展示计数，确认重复资源有独立阶段。删除无关的禁用“扫描中”按钮和常驻详细阶段表。选择继续浏览只是切换路由，扫描继续；取消请求期间显示“正在停止”，不可重复提交。

用户在进度页时完成后原地显示完成摘要和“查看结果”；在其他页面时更新状态条，不自动跳转。中断页显示重试和返回旧结果/首页。首页仍可复核上次结果，但清楚标注其归属。

报告导出继续调用已有本地实现，入口移入扫描详情；分享前展示实际包含内容的风险说明，不默认导出照片。长扫描、报告生成等动作遵守全局 `user-action-contract`，实施前需获取该技能。

报告 JSON 编码由独立 worker 处理，界面先显示“正在生成报告”，生成完成后才提供系统分享入口。离开详情取消待生成任务；取消回调不清理后来任务的状态。Debug 禁删模式提供一次失败后可重试的注入用例，不改变生产错误策略。

### 与既有规格协调

- 本轮 scan-entry 替代“点击重新扫描立即运行”为“设置确认后立即运行”；中断页的“重试此范围”不再重复打开表单。
- 本轮 scan-scope 只修改选择位置与草稿提交；自然月、日期交集、隐藏资源和无日期规则不改。
- refine-photo-analysis-pipeline 的阶段、取消、非阻塞导航全部纳入本轮完整 scan-entry 增量；expand-scan-coverage 的“确认重复内容”阶段保留。
- reconcile-post-deletion-results 的“新扫描开始即清空旧结果/摘要”与 harden-review-session 的事务式重扫冲突；最终采用后者：成功提交时重置，取消失败保留。归档上游时必须修订该完整需求及其场景；新结果不得带上一轮摘要。
- 未完成的上游质量/设备验收不得提前勾选。上游接受后再合本轮增量；若顺序不可满足，暂缓归档而不是覆盖旧安全场景。

## Risks / Trade-offs

- 扫描多一步确认 → 换取范围明确；重试无需重复设置，尚未授权不出现无效扫描设置。
- 技术信息下沉 → 首页保留局限与扫描详情入口，导出能力不移除。
- 旧结果与新扫描并存 → 明确“上次结果”，提交时合并当前用户决定，覆盖扫描/删除并发测试。

## Migration Plan

先范围表单与范围测试，再首页/报告路由，再进度状态。无持久化格式迁移；回滚可恢复旧页面入口，但必须保留事务式会话保护。分轮发布时即使第一轮 UI 未发布，唯一 ID 导航与安全结果协调仍是硬依赖。
