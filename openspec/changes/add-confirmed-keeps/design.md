## Context

当前扫描结果由 `PhotoScanResultBuilder` 构建为 `CleanupFlowState`，首页、复核页和复核箱共同读取该内存状态。用户取消某张候选的删除选择只影响当前运行周期；重新扫描会从 Photos 快照重新构建候选，无法区分“尚未判断”和“已经明确保留”。现有 `recommendedKeep` 是算法建议，允许用户逐张覆盖，不能复用为用户保护状态。

扫描仍属于超过 300ms 的用户动作并继续遵守全局 `user-action-contract`。本变更只在扫描结果发布前协调已确认保留 ID，不改变现有局部进度、取消、中断、继续浏览和失败恢复路径。

## Goals / Non-Goals

**Goals:**

- 让用户的明确保留决定跨启动、跨扫描生效，避免重复复核。
- 保持算法推荐与用户确认两个独立状态：推荐可以覆盖，确认保留必须阻止删除。
- 相似识别继续使用受保护照片作为关系和质量比较参考，新照片仍能与其组成复核组。
- 所有数量、预计体积、默认选择、复核箱和首页预览只反映未保护候选。
- 提供可发现、可撤销、可管理且支持 Dynamic Type 和 VoiceOver 的界面。

**Non-Goals:**

- 不把保护决定上传、训练模型或跨设备同步。
- 不修改 Photos 资源、系统收藏或相簿结构。
- 不对保护记录设置自动过期时间，也不基于内容哈希推断副本。
- 不放宽真实删除安全锁，不在自动化中执行真实 Photos 删除。

## Decisions

### 1. 使用独立的用户确认保护位

`CleanupCandidate` 增加 `confirmedKeep`。`recommendedKeep` 继续表示算法建议并只影响默认和批量选择；`confirmedKeep` 表示用户决定，必须从逐张删除、批量选择、复核箱和预计体积中排除。这样不会因为算法重新排序而丢失用户意图，也不会把建议误当作硬锁。

替代方案是直接把资源改成 `recommendedKeep`。该方案无法区分来源，用户也无法判断是算法建议还是自己曾经确认，因此不采用。

### 2. 只持久化 Photos 资源 ID

使用 `UserDefaults` 保存排序后的唯一 `PHAsset.localIdentifier` 集合。记录不包含照片、缩略图、视觉特征或删除历史。资源不可访问或已删除时允许保留孤立 ID；设置页只展示当前可读取的缩略图，用户可以逐项取消或全部重置。

替代方案是 SwiftData 或自建数据库。当前数据只有一个小型字符串集合，不需要迁移查询和关系模型，引入数据库会增加不必要的生命周期复杂度。

### 3. 扫描完成后按类别协调保护项

扫描和视觉分类继续读取所选范围内的本地资源。构建结果时：

1. 截图、误拍、模糊和大视频候选直接过滤已确认保留 ID。
2. 相似组保留已确认保留成员作为比较参考，并标记为不可选择的“已确认保留”。
3. 任务数量、首页预览和预计体积忽略保护成员；没有未保护可操作候选的分组不生成首页任务。
4. 发布扫描结果时再次使用当前保护集合协调，避免扫描期间用户从设置修改保护记录后发布陈旧候选。

完全在扫描入口前过滤资源会破坏相似组关系，新照片也无法与历史保留照片比较，因此不采用。

### 4. 由 AppRootView 持有保护集合并原子协调共享状态

`AppRootView` 初始化时从本地存储加载保护 ID，并向复核页和设置页下发操作闭包。确认、取消或全部重置时，同步更新本地存储和 `CleanupFlowState`：保护项目取消删除选择并移出复核箱，任务和预计体积立即重建。

复核页为每个候选提供可见的更多操作菜单。确认后展示“后续扫描不再提醒”反馈和撤销；保护照片的主点击不再切换删除选择。设置页显示保护数量和缩略图，移除后说明资源会在后续扫描再次出现。

### 5. 自动化隔离真实用户记录

UI 测试通过显式启动参数重置保护记录，避免测试相互污染。持久化用例先重置并确认样例资源，再不重置地重启 App，验证保护状态和任务数量仍然生效；所有 UI 测试继续携带 `-TrueKeepDisablePhotoDeletion`。

## Risks / Trade-offs

- [Photos ID 在删除或权限变化后不可读取] -> 允许惰性保留字符串记录；设置页仍可全部重置，不阻塞扫描。
- [保护项让相似组缺少上下文] -> 相似组保留保护成员作为只读参考，其他类别完全隐藏。
- [用户误触确认保留] -> 操作使用明确文案，完成后提供即时撤销，设置页可恢复。
- [保护项仍在复核箱或删除选择中] -> 每次保护集合变化都由共享状态统一移除对应 ID 并重建任务。
- [扫描期间保护集合发生变化] -> 扫描结果发布前使用最新集合再次协调，不发布陈旧可删除状态。
- [自动化污染真实偏好或误删] -> 使用样例 ID、显式重置参数和真实删除安全锁。

## Migration Plan

1. 增加保护存储和纯状态协调测试。
2. 接入扫描结果构建和 App 根状态，验证数量、体积、选择和复核箱同步。
3. 增加复核页确认、撤销和设置管理界面。
4. 增加跨启动 UI E2E、命名截图、无障碍审计和完整回归。

回滚时移除保护入口和存储读取即可；已有字符串集合不会修改 Photos 资源，也可以安全保留或删除。

## Open Questions

无。首版不自动保护系统收藏，不跨设备同步；后续根据真实重复候选率再评估。
