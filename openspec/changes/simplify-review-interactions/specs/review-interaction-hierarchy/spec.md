## Purpose

定义照片分组复核、完整媒体查看、复核箱和最终删除确认的统一动作层级，使用户能够区分查看、选择、确认保留、移出待删除记录与实际删除，同时保持本地处理、保守默认值及失败恢复能力。

## ADDED Requirements

### Requirement: 分组复核必须以内容和单一主操作组织

复核页 MUST 采用紧凑分组导航、可适配的照片网格和单一“加入复核箱”主操作，不得为每张照片重复常驻预览与更多按钮。直接删除 MUST 收入可发现的页面更多菜单，保留明确数量、破坏性语义和二次确认。零选择时两条清理路径 MUST 不可提交；相似、误拍、模糊等低置信度候选 MUST 默认零选择，不得重启系统推荐保留。

#### Scenario: 打开未选择的四张相似照片
- **WHEN** 用户在普通竖屏打开四张照片的相似组
- **THEN** 页面以双列展示照片，主操作处于中性禁用状态，更多菜单中的直接删除不可提交
- **AND** 不得展示推荐保留或重复的逐项预览按钮

#### Scenario: 明确选择后发起清理
- **WHEN** 用户明确选择两项
- **THEN** 主操作显示“加入复核箱（2）”，摘要仅统计这两项的预计大小
- **AND** 更多菜单“删除所选 2 项…”只进入确认，不直接调用删除
- **AND** 大小未知时必须说明未知，不能显示伪精确总量

#### Scenario: 当前分组完成
- **WHEN** 当前组不再有可清理候选
- **THEN** 页面保持稳定完成态，提供下一组或返回结果，不自动按改变后的索引打开其他组

### Requirement: 保留操作必须与删除选择明确分离

已确认保留 MUST 显示盾牌及文本，不得以整张蒙灰阻碍判断。用户 MUST 能够预览受保护照片但不能将其选入清理；即时保留反馈 MUST 提供撤销。无选择时次级操作为全部保留，有选择时只保护其余未选且未保护项，空集合不显示该操作。

#### Scenario: 保留未选择的剩余照片
- **WHEN** 四张未保护照片中两张已选择，用户执行“保留其余 2 项”
- **THEN** 仅两张未选照片获得保护，原选中两项保持选择，不得自动扩选
- **AND** 撤销只撤销该次新增保护，不恢复任何历史删除选择或复核箱记录

#### Scenario: 查看已保留照片
- **WHEN** 用户点已保留照片
- **THEN** 可以打开预览；照片保留原亮度且不出现可删除选择角标

### Requirement: 媒体查看器必须提供聚焦的浏览与恢复路径

媒体查看器 MUST 提供完整构图照片、缩放、前后切换和本地视频播放，以统一画布与工具栏组织，详情按需打开。预览、切换和缩放 MUST 不改变删除选择。请求 MUST 禁止网络并在离页时取消；本地不可用 MUST 就地解释并提供重试、切换或关闭。

#### Scenario: 查看成功的本地媒体
- **WHEN** 本地照片或视频可读取
- **THEN** 照片可查看完整构图并缩放，视频可播放，关闭后选择保持不变

#### Scenario: 加载失败后重试或切换
- **WHEN** 当前媒体本地不可用
- **THEN** 媒体区域显示原因和重试，切换与关闭仍可用，不下载 iCloud 原图，不将失败项自动选中

#### Scenario: 查看器内确认保留
- **WHEN** 用户明确确认当前资源保留
- **THEN** 保留状态在查看器内反馈且不强制退出，所有引用同步保护并取消其清理选择/复核箱记录，其他资源不自动选择

### Requirement: 复核箱必须明确表达待删除而非已删除

复核箱 MUST 以“待删除”和“尚未删除”表达状态，原“恢复选中”MUST 改为“移出复核箱”。安全说明可以渐进展开，但 MUST 明确待删除记录保留 30 天，过期只移除记录且不删除照片。移出 MUST 不新增保留保护，也不调用 Photos 删除。

#### Scenario: 移出选中项目
- **WHEN** 用户移出两条复核箱记录
- **THEN** 箱内数量和选择同步更新，原照片仍存在，不显示“已恢复照片”或删除成功

#### Scenario: 待删除记录到期
- **WHEN** 待删除记录满 30 天
- **THEN** 只清除记录，不执行照片删除，界面说明不得暗示照片会自动过期删除

### Requirement: 紧凑删除确认必须保留完整安全与结果契约

确认表单 MUST 按内容适配尺寸，在小屏或大字号下可扩展滚动。提交前 MUST 明示数量、从系统照片 App 删除、iCloud 同步影响和“最近删除”恢复路径，保留取消与破坏性确认。执行中 MUST 显示局部状态、防止重复提交；结果 MUST 按成功 ID 更新，分别报告成功、失败和仍保留项，不得宣称预计大小已永久释放。

#### Scenario: 取消删除确认
- **WHEN** 用户在确认表单取消
- **THEN** 不提交删除且选择和候选不变

#### Scenario: 删除中及部分失败
- **WHEN** 模拟删除先进入处理中再返回部分失败
- **THEN** 确认不可重复提交，成功项移除，失败项保留选择及重试，未选择/受保护项保持不变
- **AND** 反馈使用“已移至‘最近删除’”，说明仍可恢复且空间可能尚未释放

#### Scenario: 全部失败
- **WHEN** 没有任何删除成功 ID
- **THEN** 候选和选择不变，不生成成功摘要，并可查看原因与重试

### Requirement: 复核改版必须具备可访问性与可复现证据

关键操作 MUST 支持至少 44×44pt 触控、最大 Dynamic Type 和语义化 VoiceOver。自动化 MUST 显式禁用真实删除，以语义名称保留结果和失败恢复截图；测试成功反馈不得等同实际删除。真实删除验证 MUST 单独批准和显式 opt-in。

#### Scenario: 大字号和读屏复核
- **WHEN** 使用最大无障碍字号或 VoiceOver
- **THEN** 预览、选择、已保留、数量与动作可以分别读出和操作，页面可滚动且不被底部操作遮挡

#### Scenario: 非破坏性验收
- **WHEN** 执行分组、预览、复核箱和确认流程回归
- **THEN** 必须保存零选择、部分选择、保留、预览成功/失败、取消确认和删除部分失败的命名截图，XCUITest 附件保持 keepAlways
