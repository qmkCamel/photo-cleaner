# iPhone Duo 适配设计

## Context

### 已核实与未核实

2026-11-05：仓库为 `dev`，工作区包含三轮交互实现和先前删除授权持久化改动，均须保留。读取了全局 `openspec-product-delivery`、`user-action-contract`，使用 Product Design 的需求澄清原则沿用现有视觉，不生成新品牌或原型。

方案阶段：本机 Xcode 27.1（27A9275）具有 iOS 27.1 runtime、iPhone Duo device type 和已创建但关闭的 Duo 模拟器；当时仅查询配置。实施阶段已启动原生 Duo 并保存截图，当前实际窗口为 `382×644pt`，但方向请求不改变窗口。Device Hub 桌面控制权限受限，**外/内屏、半折叠和完整兼容性仍未验收**；详见文末实施记录与测试证据。设备存在不等于 App 已适配。

当前代码事实：

| 位置 | 现状 | 适配工作 |
| --- | --- | --- |
| AppRootView | 原生 TabView、首页 NavigationStack；扫描任务在根视图 | 保留原生导航，统一宽窄路由与操作所有权 |
| ReviewGroupView / ReviewBinView / ConfirmedKeepsView | 通常双列，大字号单列；缩略图多处固定 180pt | 用真实可用空间确定列数和高度，不机械拉宽 |
| TrueKeepTheme / CleanupResultsView | `tabScrollBottomPadding = 96`；额外底部补偿 | 改成容器安全区和操作区测量，检查侧边栏时的多余空白 |
| 复核/保留/扫描设置页面 | 固定底部动作区或 safeAreaInset | 小高度窗口不吞掉主要内容；动作不能与侧边系统栏重叠 |
| MediaReviewView | 本地加载、几何画布、缩放；资源 ID 定位 | 重排不重复加载；保持当前资源、播放与合理缩放状态 |
| 删除和报告呈现 | 部分 busy/sheet/task 状态属于页面实例 | 提升需要跨布局生存的状态，避免换容器即丢失任务 |
| project.yml / Info.plist | App device family=1，部署 iOS 18；未显式声明方向集合 | 核验实际构建产物和方向支持，不把缺少键直接当作锁竖屏 |

### 官方依据

以下来源于 2026-11-05 查阅，具体产品选择是本方案设计，不是 Apple 强制要求：

1. [Apple 适配入口](https://developer.apple.com/iphone-duo/prepare/)：SDK 版本会影响可用显示区域；布局应依据窗口尺寸而非主屏幕或设备方向。
2. [Prepare your app for iPhone Duo](https://developer.apple.com/videos/play/tech-talks/111461/)：测试窗口变化、非对称安全区域与分屏；复杂自定义内容可使用 reserved regions。
3. [Raise the bar with iPhone Duo](https://developer.apple.com/videos/play/tech-talks/111462/)：标准导航容器支持工具栏迁移；窄空间下需管理操作优先级和溢出。
4. [Design for iPhone Duo](https://developer.apple.com/videos/play/tech-talks/111466/)：内屏可利用多栏；系统 sheet/组件随姿态调整，应减少交互控件落在折叠区域。

本地 SDK `.swiftinterface` 已确认 `toolbarVerticalEdge`、`ReservedRegion`、`toolbarVerticalCompressionBehavior` 属于 27.1 可用 API，`topBarPinnedTrailing` 从 27.0 可用。实现时仍须对具体调用签名与 availability 做编译检查。不得臆造铰链角度或未验证的 simctl 折叠命令。

## Goals / Non-Goals

目标：所有现有流程可用；更多空间用于照片与任务上下文；形态切换不改变用户意图；危险操作状态可追溯。文字、按钮与内容不进入系统保留区域，且不能靠缩小字体满足适配。

非目标见 proposal.md。尤其不新增独立外屏场景、第二扫描会话或自动双图比较；不靠“内屏就是 iPad”来修改 device family。现有 iOS 18 支持属于产品既定要求，不额外维护一套历史交互。

## Decisions

### 1. 空间策略，而非机型分支

建立可独立单测的 `AdaptiveLayoutPolicy`（拟定名称），输入为容器可用宽高、水平/垂直 size class、Dynamic Type、系统安全区/保留区域；输出导航模式、内容限宽、列数和动作布局。不得缓存启动时尺寸。安全区只扣除一次，不混用已经 inset 的 GeometryReader 尺寸与原始屏幕尺寸。

初始产品阈值如下，单位为可用空间 pt，**不是 Duo 屏幕参数或系统断点**；实施基线可以校准，但必须同步测试和设计记录：

| 模式 | 初始判定 | 行为 |
| --- | --- | --- |
| 单面板 | horizontal compact，或可用宽度 < 720，或高度 < 480，或辅助功能字号 | 列表与详情单栈，保留当前详情，不强制返回列表 |
| 双栏 | horizontal regular、宽度 ≥ 720、高度 ≥ 480、非辅助功能字号 | 首页任务侧栏约 240–280，余下为复核详情，详情至少 440 |
| 矮窗口覆盖规则 | 高度 < 440，优先于其他规则 | 单面板；减少常驻大动作区，使用系统工具栏/紧凑动作，内容可滚动 |

双栏最小尺寸需同时满足列宽、间距和边距；不满足时退回单面板。媒体/文本分别限宽，说明段落建议上限 680pt，不把照片画布也限制到正文宽度。

网格按内容宽度计算，普通字号卡片目标最小宽度 156pt、间距 12pt、最多四列；空间不足降至一列，辅助功能字号单列。缩略图高度由卡片宽度与内容策略导出并设置合理上限；不得因屏幕变宽使图片拉伸失真。缩略图裁切保持原语义，完整预览使用 aspectFit。

### 2. 原生导航 + 自适应内容，避免三重导航

保留三个系统 Tab，不再叠加自绘全局侧栏。首页宽布局使用 NavigationSplitView 或等价系统容器承载“任务列表 / 当前复核组”；空详情提示“选择一个任务开始复核”，不默认跳入首组。复核箱、设置仍属于各自 Tab，不复制到任务侧栏。

相同任务 ID 是宽窄切换锚点：展开显示左侧定位与右侧原组，收起继续原组；返回回到来源任务位置。原生容器切换只是同一路由的两种呈现，不是两份 NavigationPath。已失效分组显示完成/不可用状态，不按索引切到下一组。

不把所有按钮都转到竖栏：返回/关闭、详情/更多、明确的主要动作使用系统 toolbar 的语义 placement；组内选择和保留留在当前内容上下文。矮窗口中主清理动作可进入系统栏，但保留数量/状态，次级动作进入可发现的菜单。删除始终为显式次路径并保留二次确认。

不长期依赖多个横向文字 toolbar item 的总宽度。关键动作不会只剩不可理解图标；图标有准确 VoiceOver 标签及数量。危险确认动作不隐藏在不可发现的溢出层级。

### 3. 全页面方案

| 页面/流程 | 单面板与矮窗口 | 足够宽的窗口 | 连续性/安全点 |
| --- | --- | --- | --- |
| 欢迎、权限说明、拒绝/受限 | 可滚动正文与单主动作；不能被系统栏截断 | 居中限宽，不拉成整屏大字卡 | 未点击授权不弹系统权限；Limited 可继续 |
| 首页结果与空态 | 任务优先；本次范围、局限和重扫可达 | 左任务列表、右复核详情；空态限宽 | 展开不默认选择首组；保留当前任务/滚动锚点 |
| 扫描范围设置 | 系统 sheet；范围可滚动，开始/取消可达 | 系统自适应表单，不自绘跨折痕弹层 | 范围草稿跨形态保留，仅明确开始提交 |
| 扫描中/完成/中断 | 当前阶段、继续浏览、取消/重试；高度不足时滚动 | 限宽状态区，不添加第二套进度 | 共用根任务，展开不重扫、不抢回首页 |
| 扫描详情/报告 | 表单与局部生成状态 | 可读限宽；系统分享入口 | 重排不触发 dismiss 取消；真正关闭按现有契约处理 |
| 所有分类复核 | 图像预览/角标选择分离；动作区随高度重排 | 详情区自适应网格；侧栏只定位任务 | ID、选中项、保留反馈与所选字节不变 |
| 照片/视频预览 | 完整画布，关闭与切换可达 | 扩展画布，信息仍按需展示 | 同一资源与播放器，不因重排重播或下载；不新增双图比较 |
| 复核箱 | 独立滚动区与操作区，说明入口可见 | 自适应网格 + 限宽选择摘要；只有一个删除主动作 | 不改“尚未删除”、记录到期和移出语义 |
| 删除确认 | 系统 sheet，安全说明可读可滚动；小高度优先更大可用呈现 | 系统控制位置，不跨折叠保留区硬居中 | 冻结请求快照，形态变化不得提交、重复提交或虚假取消 |
| 设置、帮助、隐私 | 原生 List/Form；长文换行 | 居中限宽，避免为了空间新增导航层 | 来源返回、列表位置保留 |
| 已确认保留管理 | 浏览/编辑状态清楚，大字号单列 | 自适应网格，批量动作在当前上下文 | 编辑草稿、已撤销集合不因折叠丢失 |
| 本地模型实验 | 下载/校验/切换/失败提示和取消可达 | 原生表单限宽，不重写模型策略 | 控制器单实例，切换布局不重启下载或分析 |

### 4. 安全区域、折叠与媒体

默认交互内容遵守当前窗口全部边缘的安全区域。背景可延伸，文字、选择角标、关闭、确认不得因 ignoresSafeArea 进入摄像头/系统控制区域。删除固定 96pt Tab 留白这一布局假设，保留实际需要的内容边距。

27.1 的竖向栏状态与 reserved regions 由一个小适配层读取；有系统组件可用时优先系统，不自行推导折痕或按物理设备左/右边猜测。旧系统走现有公开安全区和原生容器。RTL 使用语义 leading/trailing，但系统保留区按真实位置避让，不能把摄像头区域镜像过去。

半折叠首版承诺为“安全可用”：系统表单和控件正确避让，当前内容/任务保持。不承诺定制铰链角度驱动的双画布或上下双播放器。预览允许背景经过折叠区域，重要控制不横跨不可交互区域；若自定义控制无法可靠布置，退到系统栏或单面板。

媒体重排保留资源 ID、播放时间和播放/暂停状态；图片保留缩放比例与归一化中心，再按新可见边界钳制。尺寸改变可更新缩略图请求规格，但必须取消旧请求并按资源与请求 token 验证回调。继续 `isNetworkAccessAllowed = false`；本地资源失效进入可重试状态，不自动换另一张或扩大权限。

### 5. 状态所有权和用户操作契约

遵守全局 `user-action-contract`，这里只记录本项目差异。

| 状态 | 所有者/生命周期 | 布局切换要求 |
| --- | --- | --- |
| 当前 Tab、任务 ID、来源锚点、预览 ID、表单类型、范围草稿 | 单一 scene 级导航/呈现状态 | 外/内屏同一次使用，不创建新会话；不能同时呈现两个确认框 |
| 候选、选择、复核箱、保留和删除摘要 | 现有共享 CleanupFlowState 与存储 | 不按列号或视图索引复制；按成功 ID 协调 |
| 扫描 ID、阶段、取消请求、结果 | 现有根扫描所有者 | 重排只订阅，调用次数不增加；取消后确认停止才显示已停 |
| 删除请求 ID、冻结资源集合、busy、结果 | 布局外的单一删除协调器，复用既有服务 | 原确认视图销毁也须接收唯一结果，禁止重发；相冲突动作受同一锁约束 |
| 报告任务、生成输入快照、错误/结果 | 呈现状态关联的操作所有者 | 几何变化不等于用户关闭；真正关闭取消并拒收过时回调 |
| 媒体加载/播放器与模型控制器 | 当前资源/功能的稳定所有者 | 重排不触发额外网络/分析；真实离开时按原契约收尾 |

删除确认分为未提交与已提交：未提交保留确认快照；点击确认时校验资源、权限与保护状态，若有效集合有变化，更新数量并要求重新确认。已提交不可伪装取消或因布局重建自动重试，只能等待/核对结果，并在当前布局呈现成功、失败和保留项。系统因场景变化关闭未提交表单时明确返回“未提交删除”，不恢复为已确认状态。

折叠/旋转/分屏不是用户动作确认，也不代表持久化成功。只对已有持久化语义的数据写存储，不把每个几何 tick 写入会话。后台/进程终止沿用会话恢复契约，不承诺让 iOS 无限后台执行；未知副作用结果先核对再允许重试。

### 6. 验收矩阵与证据

先在真实 Duo simulator 记录窗口 points、scale、size classes、安全区域、栏位置和布局模式；禁止用截图像素反推固定产品尺寸。所有自动化显式禁删，测试服务调用次数和结果为可控 fixture；真实媒体成功预览使用独立非私密本地素材。

| 编号 | 验证配置 | 关键覆盖 |
| --- | --- | --- |
| D01 | 外屏两个可用方向 | 全部页面 smoke、系统侧边栏、有限权限、触控区域 |
| D02 | 内屏两个可用方向 | 单/双栏判定、第二同类任务、网格、设置/模型、sheet |
| D03 | 系统允许的分屏：最窄、中间、最大份额 | 完整关键链；不能假设精确 50:50，也不能残留另一栏 |
| D04 | 系统支持的书本/桌面/帐篷姿态 | 控件/表单避让；照片和视频本地预览；无重复提交 |
| D05 | 外→内→外及旋转/分屏连续变更 | 普通选择、保留编辑、范围草稿、扫描/取消、报告、确认未提交、删除提交后、模型下载/分析 |
| D06 | 外/内/最窄分屏 + 最大 Dynamic Type | 主操作、完整安全文案、滚动可达；保留现有 textClipped 失败并解决/给出可核验证据，不整体关审查 |
| D07 | VoiceOver、减弱动态效果、浅深色、RTL 排版压力 | 焦点不被重建抢走、顺序与语义正确、对比度/截断；RTL 只测布局不等于新增翻译 |
| D08 | iPhone 17 Pro、较小直板屏、最低 iOS 18 | 原流程无回退；新 API 不泄漏到旧运行环境 |

每个命名用例保留起始、关键处理中、结果/恢复截图。D05 至少保存“选中复核组切换”和“删除确认/处理中切换”两段连续录屏，并附服务计数/状态断言；视频不能代替断言，截图不能证明无重复副作用。

新增用例标识建议：`duo-layout-shell`、`duo-review-route-continuity`、`duo-scan-resize-cancel`、`duo-report-resize-retry`、`duo-delete-confirm-resize`、`duo-delete-inflight-resize`、`duo-media-continuity`、`duo-keeps-edit-resize`、`duo-model-task-resize`、`duo-accessibility`。XCUITest 是状态与断言主线；Device Hub 验证折叠姿态和录屏。若姿态控制无受支持自动化接口，记录可重复手动步骤，不能标成全自动通过。

截图命名 `duo-<surface>-<pose>-<width-mode>-<state>-<text-size>`，报告关联 runtime/build、用例、实际窗口参数、断言及路径。提交前重跑整套相关单元/UI 回归，不仅拼接多轮成功结果；失败不能因改版消失在清单里。

### 7. 上游规格协调

- 三轮改版规定的单主操作、图片/选择分离、推荐能力关闭、设置草稿、失败恢复继续生效。
- 第一轮“双列/大字号单列”在本方案只扩展为“按可用宽度调整、大字号仍单列”；紧凑翻组和唯一 ID 路由不变。
- “固定底部”是动作可达目标而非 Duo 必须处于物理屏幕下沿；系统侧边栏与矮窗口重排由本适配约束细化。
- `platform-support` 仅添加 Duo 构建与验收规则，不替换最低 iOS 18 需求；不激活 iPad device family。
- 实施前协调上游增量，归档先接受上游交互语义，再合入适配增量；不凭本方案覆盖上游失败与未测记录。

## Risks / Trade-offs

- 只看内屏截图可能遗漏外屏矮窗口 → D01/D03 是必过项，而非附加美化。
- 双栏与单栈重建造成任务丢失/重复副作用 → 先提取稳定状态，再改容器；测试调用次数而非只看 spinner。
- iOS 27.1 API 与最低 18 混用 → 小范围 availability 适配层，编译/最低系统测试；不复制整个业务 UI。
- 竖向系统栏空间有限 → 精简次级动作，保留唯一主操作与可发现的溢出入口。
- 当前确认页裁切告警可能是真问题或框架检测差异 → 作为发布阻断；保存完整文字、大字号和读屏证据，未确认前不得宣布误报或关闭审查。
- 宽屏多图提高内存/解码压力 → 限制可见预取，保持现有本地缓存预算；不因展开请求全量高清图。记录普通设备与 Duo 的内存、掉帧、首张加载对比，新增性能回归需解释。

## Migration Plan

### 2026-11-05 实施细化

- 首页使用永久的 `NavigationSplitView` 拓扑，不通过 `if` 替换单栈/双栏两棵视图树；空间策略仅决定其 size class 呈现。根层持有当前任务 ID 和 preferredCompactColumn。报告、范围草稿、预览和保留编辑状态留在该稳定拓扑中，删除请求单独提升为根级 `DeletionCoordinator`。
