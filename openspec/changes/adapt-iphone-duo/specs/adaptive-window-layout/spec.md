## ADDED Requirements

### Requirement: 布局必须由实时可用窗口决定

App MUST 根据当前容器的可用宽高、size class、Dynamic Type 与安全区域选择布局；MUST NOT 用机型、主屏幕固定尺寸、设备方向或启动时缓存值代替窗口几何。尺寸变化 MUST 只改变呈现，不改变清理决策。

#### Scenario: 内屏进入窄分屏
- **WHEN** 当前窗口缩小到不足以容纳任务侧栏与复核详情
- **THEN** 页面收敛为单面板，当前详情和用户选择保持不变
- **AND** 不得因设备仍处于内屏而保留溢出的双栏

#### Scenario: 窗口跨越布局边界
- **WHEN** 可用空间在单面板和双栏条件之间反复变化
- **THEN** 布局按实时空间稳定更新，列数不少于一且不超过设计上限
- **AND** 不新增导航条目、扫描或删除请求

### Requirement: 系统栏和安全区域必须正确参与布局

App MUST 使用原生导航容器承载全局 Tab 与导航/工具栏，遵守当前系统安全区域和有效保留区域。背景可延伸，但文字和交互控件 MUST 不与摄像头、系统栏或不可交互保留区域重叠；MUST NOT 假设 Tab 永远在底部或留白固定为 96pt。

#### Scenario: 工具栏迁移到侧边
- **WHEN** 系统将导航、工具栏和 Tab 放入侧边区域
- **THEN** App 不显示第二套重复全局导航，内容不保留无意义的固定底部栏占位
- **AND** 返回、主操作和更多入口可达，标签和 VoiceOver 语义准确

#### Scenario: 非对称安全区域与 RTL
- **WHEN** 当前窗口存在非对称边距或 RTL 排版
- **THEN** 交互区按真实系统区域避让，内容按语义方向排列
- **AND** 不把硬件保留区域简单镜像到另一侧

### Requirement: 宽窄导航必须保持同一任务语义

窄布局 MUST 保持任务列表到分组详情的单栈导航；满足设计空间条件的宽布局 MUST 展示任务列表和当前分组详情。两种呈现 MUST 共享唯一任务 ID，不得自动选中第一组或按分类替代任务定位。

#### Scenario: 已打开第二个相似任务后展开
- **WHEN** 用户在窄布局打开第二个同分类任务并展开窗口
- **THEN** 宽布局侧栏定位第二个任务，详情仍是该组及原选择
- **AND** 收起后仍在该详情，返回时回到原任务列表位置

#### Scenario: 宽布局没有选中任务
- **WHEN** 用户第一次进入宽布局首页且没有当前详情
- **THEN** 详情提示选择任务，不默认进入第一组、不默认选择照片

#### Scenario: 当前组已失效
- **WHEN** 重排时当前组已因处理完成或权限变化不存在
- **THEN** 显示对应完成或不可用状态并提供返回路径，不按旧索引跳入其他组

### Requirement: 全页面必须适应宽度和高度变化

引导、权限、扫描范围、进度/结果/报告、复核、复核箱、设置/帮助/隐私、保留管理和模型内页 MUST 按 design.md 的页面矩阵适配。矮窗口 MUST 保留内容滚动及关键操作，不得让常驻动作区占满视口；宽窗口不得把说明正文无限拉长。

#### Scenario: 外屏矮窗口进行扫描设置
- **WHEN** 用户在矮窗口打开扫描范围表单
- **THEN** 三个范围、当前草稿和开始/取消均可达，必要时滚动
- **AND** 不得缩小到不可读字体或隐藏有限权限说明

#### Scenario: 矮窗口浏览设置或模型任务
- **WHEN** 用户查看帮助长文或正在下载/分析的模型页
- **THEN** 正文、局部状态和恢复动作可读可达，切换布局不重启模型任务

### Requirement: 复核网格必须响应可用空间并保持保守选择

复核、复核箱与保留管理网格 MUST 根据容器宽度和字号决定列数，保持可用触控热区、图片比例、分类理由和选择语义。辅助功能字号 MUST 优先单列；宽布局 MUST NOT 因列数变化自动选择、保留或移动候选。

#### Scenario: 网格从四列降为一列
- **WHEN** 窗口缩小或启用辅助功能字号
- **THEN** 原资源 ID、顺序、选择、保留标记和所选字节保持一致
- **AND** 点图片仍预览，独立角标仍只切换选择

#### Scenario: 宽窗口显示未知大小或大视频
- **WHEN** 候选包含未知字节或大视频
- **THEN** 宽窄布局都保持真实大小/未知语义及视频信息，不能为对齐省略清理依据

### Requirement: 表单和媒体必须适应姿态及可访问性

范围、详情与删除确认 MUST 优先采用系统表单呈现，保持完整文案和动作；媒体 MUST 保持完整构图预览及本地加载边界。半折叠时 MUST 避免关键交互横跨有效保留区域，不得硬编码折痕位置或自定义第二播放器。

#### Scenario: 半折叠时打开删除确认
- **WHEN** 用户在系统支持的半折叠姿态打开确认表单
- **THEN** 数量、系统图库移除、iCloud 同步和最近删除说明均可读，确认与取消均可达
- **AND** 系统位置调整不触发任何确认行为

#### Scenario: 最大字号阅读安全说明
- **WHEN** 用户在外屏、内屏或最窄支持分屏启用最大 Dynamic Type
- **THEN** 完整说明可通过阅读/滚动获取，按钮文字不截断且不被导航或操作栏遮挡
- **AND** 系统审查失败必须保留并核实，不得整体关闭相关审查来宣布通过

#### Scenario: 预览横图或竖图
- **WHEN** 当前窗口改变比例
- **THEN** 默认预览保持完整构图，用户缩放状态按新边界合理钳制，关闭和切换始终可达
