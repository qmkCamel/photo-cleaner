## Context

最低 iOS 18，现有 `PhotoQualityScoring` 继续负责快速质量评分。语义模型不是评分器替代品，更不能拥有删除权限。遵守全局 `user-action-contract`，不复制其通用规则。

## Decisions

1. 独立 package 提供模型目录、文件安装器、结构化结果与 `PhotoSemanticAnalyzing`，MLX 实现只接收本地图片字节与本地模型路径。业务层不依赖 MLX 类型。Qwen/Gemma 共用后端，模型特定设置放入目录配置。
2. 模型固定 HF 仓库 commit 与文件清单，下载到 staging，检查尺寸及大文件 SHA-256 后原子发布；未完成下载不算就绪。文件存 Application Support、排除备份；仅用户点击下载时联网。模型移除可恢复空间，不影响照片。
3. `LocalPhotoModelController` 是 MainActor UI 状态所有者，后台 actor 处理文件和推理；一次只执行一个模型操作。取消直到任务实际退出才释放 busy，错误保留上次有效分析。关闭实验会取消任务并清空内存结果，但不删已下载权重。
4. UI 仅在显式开启后提供分析入口，每次最多四张本地候选，明确范围，使用 Photos 的无网络、aspect-fit、有方向归一化图片。照片不写磁盘、不发送给下载器。逐张推理降低峰值，暂不声称实现多图关系推理。
5. 结构化结果只包含主题、可见观察与无法判断，无选择或删除字段；结果与模型版本、输入顺序绑定。分组切换、删除和离开复核视图使其失效，取消旧任务，阻止旧结果覆盖新页面。
6. 模型入口保留许可证与来源链接。下载体积按当前固定 MLX 制品计算，不沿用 LiteRT 的体积。模拟器 UI 测试注入明确 fixture 后端，真实 MLX smoke 单独执行，不将 mock 通过等同于真机性能达标。
7. 实测 Qwen 0.8B 的 JSON 格式不稳定，使用有长度上限的单句描述适配成统一观察对象，强制 `uncertain=true`；Gemma 使用严格 JSON。禁止从畸形 JSON 猜测字段、默认为确定或把描述变成清理指令。提示词/输出格式随适配版本记录。

## Risks / Rollback

- 4-bit 不保证准确；模型可能生成无效 JSON 或错误观察，失败可重试，不改变清理状态。
- Gemma 约 3.6 GB，必须显式下载、预检空间；加载也受设备内存与热状态约束。
- MLX/Tokenizer 的兼容性以固定版本构建及真实模型 smoke 为准；设备时延和发热需要独立真机验收。
- 开关默认关闭；关闭即回到原有 Vision 流程。暂不缓存跨会话语义结果，避免模型/提示词版本导致陈旧结果。
