# 13 全页面交互优化方案

日期：2026-11-04；实现更新：2026-11-05；交付核对：2026-11-06。状态：三轮主体代码已落地；后续 Duo 改造修复了删除确认文字裁切，2026-11-05 同一应用候选完整回归 144 个单元测试及 55 个 UI 测试全部通过。专项人工、真实媒体和跨设备验收仍未完成，不作为发布或归档声明。最新证据见 [Duo 实施报告](../iOS/TrueKeep/TestArtifacts/2026-11-05-duo/README.md)，此前分轮失败记录见 [交互改版历史报告](../iOS/TrueKeep/TestArtifacts/2026-11-05-interaction-redesign/README.md)。三轮是本次交互整治顺序，不替代 [产品三阶段路线](07-three-phase-roadmap.md) 或 [既有可靠性迭代记录](11-three-round-iteration-status.md)。

## 依据与边界

依据 [本轮模拟器审查及截图](../iOS/TrueKeep/TestArtifacts/2026-11-04-design-audit/README.md)、当前代码和已认可的复核页视觉方向制定。审查在 iPhone 17 Pro / iOS 26.5 模拟器上运行了 6 个非破坏性 UI 用例；这些证据是当前界面基线，不是本方案的实现验收。

本轮未发现已证实的 P0 删除安全缺陷。优先处理 P1 的动作层级、概念误导和结果可达性，其次处理 P2 的重复说明、状态表达及一致性。媒体成功加载、视频、最大字号、VoiceOver、小屏与横屏尚需专项验证；不能把样例资源的预期加载失败判断为真实图库故障。

采用 Apple 的内容优先、明确动作层级、渐进展示及准确进度原则，不做系统样式的机械复刻。参考：[iOS 设计](https://developer.apple.com/design/human-interface-guidelines/designing-for-ios)、[按钮](https://developer.apple.com/design/human-interface-guidelines/buttons)、[工具栏](https://developer.apple.com/design/human-interface-guidelines/toolbars)、[进度指示](https://developer.apple.com/design/human-interface-guidelines/progress-indicators)。

## 三轮覆盖

| 轮次与优先级 | 页面 | 改成什么 | 可验收结果 |
| --- | --- | --- | --- |
| 第一轮 P1 | 全类别分组复核 | 图片优先、独立选择角标、紧凑翻组、一个主操作 | 无逐项重复预览按钮；预览不改选择；已保留仍可预览但不能选择 |
| 第一轮 P2 | 照片/视频预览 | 统一媒体画布和工具栏，局部失败恢复，详情按需查看 | 失败可重试/切换；成功可缩放或播放；只读预览不变删除选择 |
| 第一轮 P1 | 复核箱 | 明确待删除语义，移出与删除分层 | 不再使用“恢复选中”；30 天不被解释为自动删照片 |
| 第一轮 P2 | 删除确认 | 内容适配的确认表单 | 数量、系统相册、iCloud、“最近删除”完整可读；取消不提交 |
| 第二轮 P1 | 首页结果 | 范围/局限简述 → 摘要 → 任务，诊断下沉 | 有任务时首要内容是复核任务；重扫仍可发现 |
| 第二轮 P2 | 扫描设置 | 扫描入口打开范围表单，明确开始 | 草稿不污染当前结果；取消表单不启动扫描 |
| 第二轮 P2 | 扫描中/完成/中断 | 单进度、可继续浏览、对应状态动作 | 不重复禁用按钮；结束不抢占其他页面；取消保留旧结果 |
| 第三轮 P1/P2 | 设置/保留管理 | 任务型分组设置、浏览/编辑两态 | 真实管理入口前置；取消保护不被误解成删除 |
| 第三轮 P2 | 引导/权限/空态 | 三条必要承诺、单主操作、按原因展示空态 | 未扫描不展示完成标记；有限权限可继续；拒绝权限可恢复 |

## 第一轮：先把判断照片与安全清理做好

[OpenSpec 提案](../openspec/changes/simplify-review-interactions/proposal.md) · [设计](../openspec/changes/simplify-review-interactions/design.md) · [任务](../openspec/changes/simplify-review-interactions/tasks.md)

### 分组复核

页面从上到下：返回/分类标题/更多 → 上一组、组序号、下一组 → 简短分类理由 → 照片网格 → 选择摘要与加入复核箱 → 全部保留等次级动作。全局 Tab 不因选择变化移位。

- 普通竖屏双列；四张为 2×2，更多项滚动，大字号/窄宽改为单列。大视频保留时长与大小，分类理由不因视觉统一丢失。
- 点图片打开完整构图预览；右上角选择角标有独立至少 44pt 热区。不使用整块照片的透明蒙层表示已保留。
- 默认无选择时，底部中性禁用“加入复核箱”，文字提示“选择要整理的照片”；选中时为“加入复核箱（N）”，摘要“已选 N 项 · 预计 X MB”。未知大小不按 0 伪装为精确总量。
- “全选可清理项”是紧凑文字操作，部分选中仍为全选；全部选中后变“取消全选”。排除已确认保留，不重新引入推荐保留。
- 顶部更多中的“删除所选 N 项…”使用破坏性语义，零选择时禁用；始终经过二次确认。不以按钮数量优化为由移除直接删除能力。
- 无选择时次级操作“全部保留”；有选择时“保留其余 N 项”，只作用于未选且未保护项，N=0 时隐藏。保留结果可即时撤销，不自动选择其他照片。
- 已确认保留显示盾牌和“已保留”；点照片仍可预览。即时反馈为紧凑、支持换行的状态行，不挤占整屏；撤销后不恢复旧删除选择，用户重新选择。
- 当前组处理完成留在稳定完成态，提供“下一组”或“返回结果”；不按变化后的数组索引自动跳组。

### 媒体、复核箱、删除确认

- 媒体查看器采用统一背景和固定工具栏，关闭/前后切换/保留可发现；分类理由和大小在详情中。缩放/视频加载继续本地请求。确认保留在查看器内反馈并停留，便于继续比较；返回列表同步更新。
- 本地不可用时把解释和“重试”放在媒体区域，保留切换/关闭路径；不自动下载 iCloud，不自动勾选。保留可由用户明确选择，但不可声称已经看过原图。
- 复核箱顶部只保留“待删除 N 项，尚未删除”及选中统计，详细安全说明按需展开；“移出复核箱”是次级操作，“删除所选 N 项…”是唯一破坏性主操作。30 天说明为“待删除记录保留 30 天；过期只移除记录，不会删除照片”。
- 删除表单显示“删除 N 项？”、影响范围和取消/删除；默认适配内容，高字号可扩展滚动。执行中局部进度与防重复，结果分别显示成功/失败/保留。成功为“已移至‘最近删除’”，不得承诺永久释放了 X MB。

## 第二轮：让首页首先服务于复核

[OpenSpec 提案](../openspec/changes/prioritize-home-review-results/proposal.md) · [设计](../openspec/changes/prioritize-home-review-results/design.md) · [任务](../openspec/changes/prioritize-home-review-results/tasks.md)

- 有结果首页：标题和可见“重新扫描”工具栏入口 → 本次范围与扫描时间 → 有限访问/未读取的紧凑提醒 → 剩余预计可释放空间 → 任务列表。删除结果摘要必要时插入摘要区，不以成功反馈遮盖有限权限局限。
- 缓存命中、阶段耗时、详细覆盖和导出统一进入“扫描详情”。首页不展示整套诊断表，也不把隐私导出警告常驻在所有结果上；导出前再明确内容与分享风险。
- 初次扫描与重扫打开同一个设置表单：三个范围、有限权限说明、开始扫描/取消。默认近一个月；后续沿用最近已提交范围。取消草稿不保存，不触发扫描或权限弹窗。
- 已有扫描期间只允许一个任务：首页一个可点击状态条，不再重复放“查看扫描进度”大按钮。旧任务保持可复核并明确为上次结果，新扫描不发布半成品。
- 进度页：当前真实阶段、阶段已处理/总量（未知则不定进度）、本次范围。保留“继续浏览”和“取消扫描”，去掉无操作意义的“扫描中”按钮。快速分析、候选复核、确认重复内容、整理结果必须使用真实阶段事件。
- 完成时显示候选数量、局限和“查看结果”；用户在其他页面时只更新状态，不强制跳转。中断时显示原因、“重试此范围”和“返回上次结果”（没有旧结果则返回首页）。
- 成功提交新结果时重置上一轮删除摘要；失败/取消时连同旧结果一起保留。权限变化和保留/删除决定在提交前仍需重新协调，不能让扫描快照复活已经处理的内容。

## 第三轮：设置与首次使用回归简单

[OpenSpec 提案](../openspec/changes/reorganize-settings-and-onboarding/proposal.md) · [设计](../openspec/changes/reorganize-settings-and-onboarding/design.md) · [任务](../openspec/changes/reorganize-settings-and-onboarding/tasks.md)

- “设置”标题与 Tab 一致。分组顺序：整理管理（已确认保留与数量）、帮助与隐私（如何工作、数据与隐私、帮助支持）、进阶（本地模型实验及状态）；版本为页尾信息。
- 不凭设计稿新增没有业务实现的设置项。模型实验内部先补截图审查，仅改入口顺序；不在本轮随意重写下载或模型策略。
- 保留管理默认只展示图片和状态，点图可只读查看，右上“编辑”。编辑态支持逐项/全选并显示“取消所选保留（N）”；全部取消另需确认。撤销保护明确“不会删除照片，可能在之后扫描再次出现”。空列表不展示批量按钮。
- 引导保留产品用途与三个必要承诺，然后“开启照片访问”；“暂不”是轻量次级操作，说明详情是链接。系统权限弹窗必须在说明后由用户操作触发。
- 无权限：解释原因与设置/授权入口；未扫描：开始整理/扫描相册；扫描无候选：本次范围内暂无候选；处理完：本轮没有待复核项目；无保留：引导到照片预览中的保留操作。不同原因不共享“扫描成功”勾号和同一句空态。

## 全局约束与验收

1. 保留现有品牌颜色、语义字体及导航，不将本轮扩大为品牌、识别算法、付费或基础架构改造。
2. 低置信度默认不选、确认保留不可删除、二次确认、有限访问和本地不上传全部保留。直接删除是显式次路径，不是自动清理。
3. 真实状态仍由共享扫描/复核状态、ConfirmedKeepStore、ReviewSessionStore、删除服务持有；页面只拥有选择草稿和呈现状态，避免重复事实来源。
4. 超过 300ms 的动作实施前读取全局 `user-action-contract`，项目仅记录差异，不复制通用规则。2026-11-05 已读取并应用该技能：扫描任务由根状态持有、取消等待停止、重复扫描拦截、导出脱离主线程且离页取消；删除使用既有服务及确认链，部分失败保留恢复上下文。
5. 所有关键触控目标至少 44×44pt；最大 Dynamic Type 可换行、可滚动，VoiceOver 区分预览、选择、已保留及失败状态。先保证语义和可达性，再做视觉微调。
6. 每轮保留命名截图：正常、选中/成功、失败/恢复、大字号。XCUITest 用 `XCTAttachment.keepAlways`；Mirror/AppClaw 流程保存步骤、断言和截图。录屏用于验收动画/跳转，不能替代状态断言。
7. 自动化明确传入 `-TrueKeepDisablePhotoDeletion`，使用可控 fixture；成功媒体测试使用专门的非私密本地测试照片/视频。真实删除另行制定计划和 opt-in，不以当前手机已授权为测试许可。
8. 运行基线同设备尺寸对比，补小屏、最大字号、VoiceOver、横屏和 iOS 18 最低版本适配；截图库只是视觉证据，不等于真实图库准确率或真机性能结论。
9. 每轮独立记录实现与验收状态，可按用户要求连续实施；不得把某一轮通过冒充三轮全部接受。未验收项保持未勾选，不提前归档。

## 规格协调与不做事项

历史提案存在“推荐保留”“两条删除动作同级”“点击即扫描”“新扫描开始即清空结果”等旧表述。三轮 design.md 列明最终选择和前置规格；实现/归档前必须按最终接受顺序协调，禁止旧增量覆盖新交互。既有未完成的真实图库、设备性能等验收仍保持未完成。

不在本轮做：自动删除、推荐保留重启、全量高清扫描、iCloud 原图自动下载、账号云同步、新的真实删除设置、全新视觉品牌、未经审查的模型实验内页重做。若补测发现真实功能缺陷，另开对应问题，不借视觉改版扩大范围。
