# 10 当前识别策略

本文档记录当前 iOS MVP 如何识别清理候选，以及后续引入端侧 AI 时应遵守的边界。

核心原则：当前版本只产出“值得复核的候选”，不自动判断“可以删除”。用户明确选择候选后，可以加入复核箱继续汇总复核，也可以从当前复核组直接发起删除；两条路径都必须经过删除前二次确认，才会请求系统 Photos 删除。

实现入口：

- `iOS/TrueKeep/TrueKeep/Services/PhotoLibraryScanner.swift`
- UI 示例数据在 `iOS/TrueKeep/TrueKeep/Data/SampleCleanupData.swift`，只用于 `-TrueKeepUseSampleCleanupData`、截图和 UI 自动化，不代表真实扫描结果。

## 当前真实扫描范围

扫描只读取用户授权范围内的 Photos 资源：

- Full Access：扫描完整可访问图库。
- Limited Access：只扫描用户授权给 App 的照片和视频，并在 UI 中提示结果可能不完整。
- 隐藏资源不纳入扫描。
- 缩略图和视觉分类请求不允许 iCloud 网络下载，避免为了分类触发云端取图。

当前真实扫描覆盖五类候选：

- 截图和聊天截图。
- 占空间的大视频。
- 短时间内相似照片。
- 疑似误拍。
- 疑似模糊或遮挡。

## 分批和性能边界

扫描按批处理，避免一次性阻塞 UI：

- 标准批大小：`200`
- 低电量模式批大小：`50`
- 标准视觉分类上限：最新 `300` 张非截图照片
- 低电量模式视觉分类上限：最新 `80` 张非截图照片

截图和视频候选来自 Photos 元数据扫描；相似、误拍、模糊候选来自本地图像视觉指标。相似照片优先使用 Vision feature print；总体质量由 iOS 18 系统内置的 Vision 图片美学模型评分，人脸拍摄质量辅助相似组推荐保留。亮度、饱和度和边缘清晰度规则继续负责可解释原因，并在 Vision 请求失败时确定性兜底。

## 候选规则

### 截图

使用 Photos 系统 subtype：

- `asset.mediaSubtypes.contains(.photoScreenshot)`

这类候选的解释文案是“系统识别为截图，可能是临时信息。”

### 大视频

当前真实扫描主要按时长判断：

- `duration >= 300` 秒，即 5 分钟以上。

代码也支持未来接入真实文件大小后按大小判断：

- `estimatedBytes >= 500_000_000`，即约 500 MB 以上。

目前视频大小展示仍可能是估算值，不应当对外承诺精确释放空间。

### 相似照片

只处理非截图照片。当前流程：

1. 请求 224x224 本地图像缩略图。
2. 降采样为 32x32 像素。
3. 计算本机视觉指标：Vision feature print、感知 hash、亮度、饱和度和边缘清晰度。
4. 运行 iOS 18 Vision 图片美学评分，并在可用时读取人脸拍摄质量。
5. 按创建时间从新到旧排序。
6. 两张照片满足以下条件时归为相似：
   - 创建时间差不超过 `180` 秒。
   - 如果两张照片都有可比较的 Vision feature print，feature-print distance `<= 0.16`。
   - 如果 feature print 不可用或不可比较，回退到感知 hash 汉明距离 `<= 8`。
7. 如果 Vision feature print 可比较但距离超过阈值，不再用 pHash 把这两张照片兜底分组。
8. 每个相似组内，将推荐保留分最高的一张标为“推荐保留”：没有人脸质量时使用总体美学质量；有人脸质量时使用 `80%` 总体质量与 `20%` 人脸质量。

推荐保留项默认不加入删除选择，批量全选也会跳过；用户仍可逐张主动选择或取消。

### 用户确认保留

用户可在复核页把照片标为“已确认保留”。该状态与算法生成的“推荐保留”相互独立，只在本机保存 Photos 资源 ID：

- 已确认保留项不进入默认或手动删除选择、复核箱、待复核数量和预计释放空间。
- 后续扫描过滤截图、误拍、模糊和大视频中的已确认保留资源。
- 相似照片分析仍允许已确认保留项作为受保护的比较参考，但不会把它计为待复核候选。
- 设置页取消保护后，资源可在当前结果协调或后续扫描中重新成为候选。

### 疑似误拍

只对未进入相似组的非截图照片判断。当前误拍风险融合两类本地信号：

- Vision 图片美学分低于 `0` 且不是 utility 图片时，使用 `max(0, -overallScore)` 作为模型风险。
- 亮度、色彩和清晰度启发式继续提供极端曝光和低画面信息风险。
- 两类风险取最大值；Vision 失败时只使用启发式风险。

启发式误拍风险基于以下信号：

- 过暗：亮度 `< 0.11`
- 过亮：亮度 `> 0.92`
- 低饱和且低清晰度：饱和度 `< 0.045` 且清晰度 `< 0.015`

融合后的误拍风险达到当前阈值 `0.85` 时，才会标记为疑似误拍。这意味着只有 `overallScore <= -0.85` 的非 utility 图片才可能单独被模型召回。utility 标记本身永远不会创建误拍候选。这类结果属于低置信度候选，默认不选中。

### 疑似模糊或遮挡

只对未进入相似组、且未被标为误拍的非截图照片判断。Vision 图片美学 API 不公开单独的模糊原因，因此当前仍使用边缘清晰度生成可解释的模糊风险。

启发式模糊风险会在边缘清晰度较低时升高；风险达到当前阈值 `0.85` 时，才会标记为疑似模糊或遮挡。这类结果属于低置信度候选，默认不选中。

## 默认选中策略

默认选中不是“自动删除”，只是进入逐组复核时的初始选择。

默认选中：

- 截图。
- 大视频。
- 相似组中非“推荐保留”的项目。

默认不选中：

- 疑似误拍。
- 疑似模糊或遮挡。
- 相似组中的“推荐保留”项目默认不选中。

用户可以在复核页修改选择；推荐保留项不会被默认或批量选中，但允许用户逐张覆盖推荐，明确选中后可以加入复核箱或直接删除。

## 当前限制

- 没有云端 AI。
- 没有人脸、主体、语义内容、纪念价值判断。
- 不识别“孩子”“宠物”“票据”“证件”等具体语义类别。
- 相似照片已优先使用 Vision feature print，但阈值仍需要真实照片库校准。
- 最低支持系统已经提升到 iOS 18，不再保留 iOS 17 的规则-only 运行分支。
- Vision 美学评分是综合黑盒分数，不会提供单独的模糊、曝光或误拍原因；候选解释仍来自可核验的本地图像指标。
- `isUtility` 只表示图片可能偏工具用途，不等于低价值或可删除，当前不会单独产生候选。
- 误拍、模糊仍是低置信度复核候选，不是高置信删除判断。
- 视觉分类只覆盖最新一部分照片，受低电量模式影响。
- iCloud-only 且本地无缩略图的资源可能不会进入视觉分类。
- 释放空间目前可能是估算，不应作为精确存储统计使用。

## 后续端侧 AI 方向

可以引入端侧 AI，但建议分阶段做，并保持“候选复核”产品原则不变。

### 适合优先引入的能力

1. 校准相似/重复聚类

   当前已接入 Vision feature print 优先路径。后续需要用真实照片库样本校准 `0.16` distance 阈值，并确认低电量模式、老设备和大图库下的耗时表现。

2. 校准 Vision 美学评分和人脸质量权重

   当前使用 `overallScore <= -0.85` 作为模型单独召回疑似误拍的保守门槛，相似组推荐保留使用 `80%` 总体质量与 `20%` 人脸质量。后续需要用真实家庭照片库验证阈值和权重，尤其关注暗光纪念照片、儿童连拍、票据和文档等困难样本。

3. 训练可选的轻量误拍模型

   先收集 Vision 与启发式的误报、漏报和人工标注样本，再决定是否训练图片输入的轻量 Core ML 模型。模型仍只输出低置信度复核候选，不允许自动删除。

4. 解释摘要

   将模型分数转成可解释原因，例如“画面过暗”“主体不完整”“与前后照片高度相似”。解释要来自可核验信号，避免泛泛写“AI 判断”。

### 不建议首批做的能力

- 自动删除。
- 云端上传分析。
- 用语义模型判断“这张照片没有纪念价值”。
- 用黑盒分数默认选中低置信照片。
- 在没有设备分层和能耗测试前全图库跑重模型。

### 建议的上线门槛

引入端侧 AI 前，至少满足：

- 模型只在本机运行，且隐私文案同步更新。
- 有设备能力分层：高性能设备启用完整模型，低性能或低电量模式降级到轻量规则。
- 有耗时动作局部进度，不阻塞其他导航。
- 所有模型候选都有可解释原因。
- 低置信候选默认不选中。
- 有真实设备误删风险评估和人工标注样本回归集。
- App Store 文案不夸大“AI 自动清理”，只承诺“本机识别复核候选”。

## 当前判断

端侧 AI 值得做，但不应该改变 TrueKeep 的信任模型。更好的定位是：

> AI 提高候选质量和解释质量，用户保留最终删除决定权。

短期优先级建议：

1. 先收集真机扫描质量反馈，确认 Vision 美学评分与现有解释规则的误报/漏报。
2. 优先校准疑似误拍阈值、相似聚类阈值和人脸质量权重。
3. 暂缓语义价值判断，尤其是家庭照片场景里“低质量但有纪念意义”的误删风险很高。
